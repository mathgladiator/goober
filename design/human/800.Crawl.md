# Crawling: Goober as a Good Robot

> Drafted by Claude on 2026-10-27 at the human's request, for the human to edit and own.
> What the host builds of it is recorded in `design/machine/017.Crawl.md`.

Some products start with what other people have already put on the web. For example, I want a
local index of meat: which ranches and butchers are near me, what they sell, what it costs,
and when it is in stock. Nobody publishes that as one feed. It is scattered across small
websites, Shopify stores, farm platforms, and Facebook pages. Building it means visiting those
sites on a schedule, pulling out what matters, and keeping it current.

So goober needs to be able to read the web, and to do it like a good citizen. The host owns
the fetching, the same way it owns the network in the larger environment: boxes and agents
say what they want to read, and the host decides how and whether it goes out.

## The host is the robot

Every fetch goes through the host, never around it. That gives us one place to be polite and
one place to be safe.

Polite:

- **robots.txt is obeyed**, including Crawl-delay. A site that says no gets no visit.
- **The robot says who it is.** A User-Agent names goober and gives a way to reach the
  operator, so a site owner who is unhappy knows who to tell.
- **One site at a time, slowly.** The host keeps at most one request in flight per site, with a
  minimum gap between requests, and backs off on 429 and 503 (honoring Retry-After).
- **Nothing is fetched twice for no reason.** Pages are cached, and refetches are conditional
  (ETag and Last-Modified), so an unchanged page costs the site almost nothing.
- **No sneaking.** No logins, no paywalls, no solving challenges, no pretending to be a browser.
  If a site doesn't want to be read by a robot, we don't read it.
- **Opting out is easy.** The host keeps a list of sites that asked not to be crawled, and it
  wins over everything.

Safe:

- **Only the public internet.** The host resolves every name itself and refuses private,
  loopback, link-local, and other special addresses, on every hop of every redirect, so a
  crawl can't be turned against the machine it runs on or the network behind it.
- **Bounded.** Every fetch has a size limit, a time limit, and a list of content types worth
  reading (HTML, text, JSON, XML, feeds). Images and video are not fetched.
- **Audited.** Every fetch is a line in the egress log.

## What a page becomes

Raw HTML is the worst possible thing to hand an agent or a box: it is huge, noisy, and mostly
navigation. The host keeps the full HTML, and offers views that simplify it:

| view | gives |
| --- | --- |
| html | The page as fetched. |
| text | The visible text, with block structure kept as line breaks. |
| markdown | Headings, paragraphs, lists, links, tables, and emphasis as markdown. |
| links | Every link, resolved to an absolute URL, with its text and rel. |
| meta | Title, description, canonical URL, language, Open Graph, and feeds. |
| jsonld | The page's schema.org JSON-LD blocks, parsed. Product, Offer, and LocalBusiness live here on many small business sites. |
| tables | Each table as headers and rows. |
| select | The elements matching a CSS selector, each with its text and attributes. |
| extract | Records: one per element matching an item selector, with named fields from selectors within it. |

`extract` is how a domain-specific scraper is written without code. For a farm store that lists
its cuts as cards, the scraper is three selectors:

```json
{
	"items": ".product-card",
	"fields": {
		"name": ".product-title",
		"price": ".price",
		"url": "a@href"
	}
}
```

When selectors aren't enough, a box does the rest in code: it asks for the views it needs and
decides what they mean.

## Who can crawl

- **Operators and their agents** fetch any page and run crawls through the operator API, so an
  agent like GrokBot can look at a site, try selectors, and set up a crawl in one sitting.
- **Boxes** declare the web as a service in their manifest, with the sites they may read (or
  any site), and call it like any other service. The answer is the views they asked for. A box
  that crawls owns its frontier and its results in its own database, and walks them with a
  timer, so a domain-specific crawler is an ordinary box.

## Crawls

A crawl is a job the host runs in the background: seed URLs, a scope (the same site, a URL
prefix, include and exclude patterns), limits (pages, depth), and whether to read sitemaps. It
follows links within scope, respects nofollow, and records every page it visits. With an
extract spec, it pulls records out of each page as it goes; JSON-LD is always captured. An
agent reads the results as pages or records, and can run the same crawl again later to see
what changed.

## The meat index, as an example

1. An agent finds ranches and butchers near me (through a search service, or by hand) and adds
   them to a box as sources.
2. For each source, it looks at the site through the views: is there JSON-LD with products?
   Is it a Shopify store, which publishes its catalog as JSON? Or does it need an extract spec?
   It records what works.
3. A timer in the box walks the sources weekly, fetches through the host, and updates offerings:
   the cut, the price, the unit, whether it is in stock, and when we last saw it.
4. The index is served from goober as pages and as MCP tools, so I can ask an agent "who near me
   has a quarter beef in November?"

## Not in scope

- Bypassing anything a site does to keep robots out.
- Collecting personal information about people. Businesses, their offerings, and their public
  contact details are the point; individuals are not.
- Rendering JavaScript. Pages that only exist after scripts run are skipped for now; many of
  them have a JSON endpoint or JSON-LD that is better anyway.

## Open questions

- How the opt-out list is published, and whether a site owner can add themselves to it.
- Whether results from one box's crawls can be shared with other boxes, or only through
  internal routes.
- Whether rendering JavaScript (a headless browser) ever belongs in the host, or in a separate
  service the host calls.

# The Operator API

Everything about operating and deploying the system can be done through either an MCP tool or an API call, so a CLI tool, a script, or an agent can do it. The only exception the system enforces is approval: a deployment that isn't fully covered by automatic approval policies must be approved by a person in the operating panel's UI.

This document lists the whole API. Every operation below is available both as an HTTP call under the reserved /goober-operations/ prefix and as a tool on /goober-operations-mcp, with the same name, the same inputs, and the same host roles, as described in the operating panel design. The names here are the tool names; the HTTP form is the same name as a path.

Every call is made as a host identity, checked against host roles, and written to the audit. Most of the system was designed as implicit contracts between its parts, and this list is where those contracts become explicit: if an operator can do it, it is here.

## Roles

| role | can call |
| --- | --- |
| host:observer | Everything that reads. |
| host:operator | Everything that reads, plus tuning, traffic within approved plans, and operational actions like retries, sweeps, drains, and rotation. |
| host:owner | Everything, including domains, host roles, quotas, schemas, migrations, and keys. |
| Agents | The same as the person who connected them, except that no agent can enter or replace a key, and no agent can approve anything. |

## Versions and deployment

| operation | does | from |
| --- | --- | --- |
| version_upload | Uploads a manifest and its WASM module, or a config with no module, as one artifact, and returns the new version id. | Deployments |
| version_get | Returns a version's manifest, state, pins, and approval record. | Deployments |
| version_list | Lists a box's or config's versions, and which are primary, shadow, and secondary. | Approvals |
| version_diff | Returns the readable diff of a version against the current primary, grouped into kinds of change. | Approvals |
| version_check | Returns the checker's reports for a version: worst cases, bundles, conflicts, type compatibility, reach. | Approvals |
| version_approval_status | Says whether a version was approved by policy, is waiting for a person, or was declined. | Approvals |
| version_set_mode | Sets an approved version's deployment mode: go, slow, or shadow, with its period. | Approvals |
| version_promote | Makes an approved version primary. | Deployments |
| version_rollback | Moves traffic back to the previous primary. | Deployments |
| version_retire | Stops a version from receiving traffic, drains it, and keeps it. | Deployments |
| version_delete | Deletes a version that never received any traffic. | Approvals |

Approving or declining a version that policies don't cover has no API. It happens only in the panel's UI, by a person.

## The invariants

- **Everything has an API, except approval.** Anything an operator can do, a CLI or an agent can do too, except approving what policies don't cover.
- **Every call is a host identity's.** It is checked against host roles and written to the audit.
- **The API and the MCP tools are the same.** Same names, same inputs, same roles.
- **Values only come from people.** Keys are entered by people, never by agents, and never read back.
- **This list is the whole list.** A new operation is added here before the host offers it.

# Quotas

Since goober is going to start by managing SQLite instances and their schemas, operators can interact with every database at a holistic level, like measuring its size or setting quotas.

Quotas per domain are an important topic, so we enforce them at two levels to start, the identity and database insertion level and the upload process, and there are others to concern ourselves with in the future.

A single tenant can be scoped to a limited number of users, which means we monitor it and have red lines when tenants are getting close. Similarly, specific databases (and database patterns) can have quotas, and these are enforced in the runtime to ensure a database stays within a fixed row count. Uploads can have a quota applied, such that files no longer upload once it is reached, since space is a premium asset (well, maybe not now, but yes, it is to be managed at the tenant level).

## Who sets quotas

Quotas belong to the operators of the host, not to the products, since they are about what a tenant may consume from the platform rather than what a box can do. They live in host configuration, with defaults for every domain and overrides for specific ones, and operators change them from the operating panel without deploying anything.

```json
{
	"quotas": {
		"defaults": {
			"users": 25,
			"databases": {
				"tenant_*": { "rows": 1000000, "bytes": 1073741824 }
			},
			"uploads": { "bytes": 5368709120, "files": 50000 }
		},
		"domains": {
			"bobsplumbing.com": {
				"users": 100,
				"uploads": { "bytes": 21474836480 }
			}
		}
	}
}
```

Database quotas are set by database pattern, like tenant_*, using the same names that strategies resolve to, so one line covers every tenant's database. A domain's override only names what differs, and everything else falls back to the defaults, the same way configs work.

## Where quotas are enforced

| quota | enforced at | when it is reached |
| --- | --- | --- |
| Users per tenant | The identity service, when a new account would be created in the tenant's realm | Sign-up is refused with a clear message, and existing users are untouched. |
| Rows per database | The host, when a write is accepted into a request's write set | The generated write function returns false with a quota reason, and the box answers however it likes, usually with a 4xx that tells the person why. |
| Bytes per database | The host, when a bundle commits | The commit is refused, the request answers with a 507, and nothing in the bundle happens. |
| Upload bytes and files | The upload pipeline, during preprocessing | The upload is refused before the box ever wakes up, with a 413 for a single file that is too big, or a 507 when the tenant is out of space. |

Enforcement happens in the host, where the numbers already live: SQLite knows its page counts, the strategies know every insert, and the upload ledger knows every byte. A box never counts anything for a quota, and can't get around one, since every write and upload passes through the host before it lands.

## Red lines

A quota that is only enforced is a quota that surprises people, so every quota also has red lines that warn before anything is refused:

| line | what happens |
| --- | --- |
| 80% | The tenant appears in the operating panel's quota view, so operators can see who is growing. |
| 95% | The tenant's owner is told, on their account pages and by email from the system mailer, with what is running out and what to do about it. |
| 100% | The quota is enforced, and every refusal is counted in the operating panel, the same way urgent key requests are, so operators can see which tenants are hitting the wall and how often. |

## What comes later

Users, rows, bytes, and uploads are where we start, because they are what fills a disk. The others to concern ourselves with in the future, each enforced the same way, in the host, with the same red lines:

- **Requests per day,** so a viral product can't starve its neighbors on the same host.
- **External calls and emails per day,** since those cost money or reputation outside the platform.
- **CPU time,** measured per box per tenant, which the operating panel already records.
- **Open subscriptions,** since every open SSE connection holds memory.
- **Timers,** since a source with a million active rows is a million fires.

## The invariants

- **Quotas belong to operators.** They live in host configuration, never in a manifest, and change without a deployment.
- **The host enforces every quota.** A box never counts for a quota and can't get around one.
- **Nothing is refused without a warning first.** Red lines at 80% and 95% come before enforcement at 100%.
- **A refusal is clear and counted.** The person sees why, and the operators see how often.

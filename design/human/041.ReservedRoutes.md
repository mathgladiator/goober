# Reserved Routes

The host owns a handful of routes itself: sign-in, operations, hooks from the services around it, and the plumbing that makes uploads, drafts, and agents work. No box, config, static entry, or rewrite can ever declare them, on any domain, and the checker refuses any manifest that tries. This document lists every one, so that there is exactly one place to check before choosing a path.

Reserved routes are never part of a conflict, since nothing else can claim them, and no traffic plan can move them. They belong to the host, and only to the host.

## Reserved HTTP prefixes

Anything under these prefixes belongs to the host, on every domain:

| prefix | what lives there | defined in |
| --- | --- | --- |
| /.well-known/ | OAuth metadata, and anything else a standard puts there, like certificate challenges, which Caddy answers itself | Identity, The system around |
| /oauth/ | The OAuth 2.1 endpoints: authorize, device, token, register, and revoke | Identity |
| /identity/ | Sign-in, passkeys, emailed codes, the account page, sessions, and the screens where people enter their own keys | Identity, Keys |
| /mcp | The MCP endpoint for agents, which serves each box's tools and resources | MCP |
| /goober/ | Host features offered to browsers and agents: the client script, resumable upload transfers, and working set editing | UI, Files, Working set |
| /goober-operations/ | The operating panel | Operating panel |
| /goober-operations-mcp | The operating panel's MCP tools | Operating panel |
| /internal/ | Hooks and calls from the host's own infrastructure, never from the public internet | This document |

## Reserved internal routes

Everything under /internal/ is reachable only from the host's private interface, and every call must carry the credential of the service making it. These are how the infrastructure around the host talks to it:

| route | called by | does |
| --- | --- | --- |
| /internal/routes/mta/stalwart | Stalwart's MTA hooks | Converts SMTP conversations into mail routes, as described in the mail design. |
| /internal/routes/mta/$server | Any future mail server | The same, for a mail server other than Stalwart. |
| /internal/routes/tls/ask | Caddy's on-demand TLS | Answers whether a domain is registered, and verified when the host requires it, as described in the domains design. |
| /internal/rpc/ | Other hosts in the cluster | Internal calls between boxes and forwarded requests, as described in the internal messaging and cluster designs. |

## Reserved mail addresses

| address | why |
| --- | --- |
| postmaster@ | Mail standards require every mail domain to accept it, so the host delivers it to the operators. |
| abuse@ | The conventional address for reporting abuse, so the host delivers it to the operators. |

A catch-all route, "*@", never receives these, since they are claimed by the host before any route is consulted.

## Reserved names

Some reservations aren't paths, but they follow the same rule: no manifest may take them.

| reserved | where | why |
| --- | --- | --- |
| goober_ | The start of route names, strategy labels, counters, and MCP tool names | Generated code and host-provided MCP tools, like working_set_put, use it, and nothing a box names may collide with them. |
| Names starting with "!" | Parameters, fields, and roles | They are reserved identifiers, as described in the reserved identifiers design. |
| host: | The start of grant roles | Host roles, as described in the identity design. |
| /, : | Inside substituted values | They separate scopes and namespaces in roles, so no value may contain them. |

## The invariants

- **Reserved routes belong only to the host.** No manifest, config, static entry, or rewrite may declare, shadow, or rewrite to or from them.
- **Reserved routes are never in conflict.** Nothing else can claim them, so no traffic plan ever involves them.
- **Internal routes are private.** They are reachable only from the host's private interface, and only with the calling service's credential.
- **This list is the whole list.** A new reserved route is added here before the host ever answers on it.

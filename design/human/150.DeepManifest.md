# Deeper on Manifests

A manifest ultimately is the shape of a box. It is a flat, single file that controls the routes, the data flowing in, the data updates, and the service calls. It is the executive summary of what a box can do. Now, a box can be tiny or large, so a manifest can be small or very large. Manifests are artifacts that represent a concrete plan of what the box is supposed to do, along with documentation of what the mission of the box is.

This document gathers every partial idea about manifests from the rest of the design into a single whole: what a manifest is, the two kinds of manifest, the rules every field obeys, and a definition of every field. When this document and another disagree about a field, this one is meant to be right, and the other one should be fixed.

## Two kinds of manifest

| kind | identified by | has a box | can declare |
| --- | --- | --- | --- |
| Box manifest | "box": "$box_name" | Yes, a WASM module deployed with it | Everything in this document. |
| Config | "config": "$config_name" | No | Only what the host can do by itself: domains, static content, templates, headers, rewrites, and the working set, plus the fields that govern deployment. |

A manifest has exactly one of box or config. Everything that needs code to answer, like dynamic routes, data, external services, timers, and counters, needs a box, which is what the configs design means by "the lack of a box prevents some functions."

## Rules every field obeys

- **Naming.** Keys the platform defines are lowercase words joined by hyphens, like timeout-ms. Names people choose, like route names, strategy labels, parameters, and type fields, can use any style, like hello_world or getForecast, as long as they are valid identifiers: letters, digits, and underscores, not starting with a digit, and not starting with goober_ or "!". Keys borrowed from another format, like OpenAPI's operationId, keep that format's spelling.
- **Types.** Every type is an OpenAPI type, written inline as a small schema, or as a shorthand inside braces in paths and addresses, as described in the JSON design.
- **Substitution.** {!name} is a reserved identifier the host sets, {name} is a route or query parameter the caller chose, and {name*} is a rewrite tail, as described in the reserved identifiers design. No substituted value may contain "/" or ":".
- **Reserved identifiers.** Names starting with "!", like !user_id and !tenant, can only be set by the host. No route parameter, query parameter, schedule field, or grant role may start with "!" or take a reserved name.
- **Reserved namespaces.** "/" separates tenant namespaces in grant roles, and "host:" marks host roles, which only operators can grant. No substituted value may contain "/" or ":", and no grantable or revocable option may name a host role.
- **Reserved routes.** No manifest may declare a route, static entry, or rewrite under a reserved prefix, like /oauth/ or /internal/, or take a reserved name, as listed in the reserved routes design.
- **Deny by default.** Anything a caller can reach must say who may reach it, through requirements, "public": true, or callers, as the reachability table below spells out.
- **Immutability.** A deployed manifest never changes. Any change is a new version, named by the hash of the whole artifact.

## The top level

```json
{
	"box": "jobs",
	"mission": "Track the jobs a trade business has booked, and tell people when they change.",
	"domains": ["*"],
	"types": "jobs.openapi.json",
	"pins": {},
	"policy": [],
	"deployment": { "mode": "go" },
	"behavior": {},
	"routes": {},
	"data": {},
	"external": {},
	"keys": {},
	"static": {},
	"templates": {},
	"headers": {},
	"rewrites": [],
	"counters": [],
	"working-set": {},
	"content-security": {}
}
```

| field | type | default | needs a box | defined in | meaning |
| --- | --- | --- | --- | --- | --- |
| box | string | one of box or config is required | Yes | Approvals | The logical box this manifest describes. |
| config | string | one of box or config is required | No | Configs | The name of a config, which is a manifest with no box. |
| mission | string | none | No | Introduction | What the box or config is for, in plain words, read by humans and agents. |
| domains | array of string | required | No | Domains, Conflicts | The domains this manifest applies to, or "*" for every domain. |
| types | string | none | No | JSON | The OpenAPI document whose components.schemas hold the named types. |
| pins | object | filled in at deploy | No | Stability | The versions of everything outside the box that can change it. |
| policy | array of string | none | No | Approvals | Kinds of change that don't need a human to approve. |
| deployment | object | mode go | No | Approvals | How an approved version goes live. |
| behavior | object | see below | Yes | Manifest, Operating panel | How the box runs. |
| routes | object | none | Yes | Manifest and each protocol's design | Everything a caller can reach that needs code. |
| data | object | none | Yes | Data flow, Shape of data, Time, Bus | Data strategies. |
| external | object | none | Yes | Network, Outbox, Mail, Internal messaging | Services and other boxes this box calls. |
| keys | object | none | No | Keys | Kinds of key a tenant or person enters for this product. |
| static | object | none | No | UI | Static content embedded by path. |
| templates | object | none | No | UI | Mustache templates embedded by name. |
| headers | object | none | No | Configs | Header properties, with priorities. |
| rewrites | array of object | none | No | Configs | Rewrite and redirect rules. |
| counters | array of string | none | Yes | Operating panel | Named counters the box can increment. |
| working-set | object | none | No | Working set | Who may edit and approve a live draft of the static content. |
| content-security | object | scripts and forms off | No | Static bundles | What the rogue content checks allow in static content. |

## Routes

Every route lives at routes.$protocol.$path.$verb, where the path is a URL path, a tool name, or an address, depending on the protocol. Timers are the one exception: they live at routes.timer.$name, with no verb, since firing is the only thing a timer does.

| protocol | key | verbs | defined in |
| --- | --- | --- | --- |
| http | A path, like /jobs/{job_id : int64} | get, post, put, patch, delete, upload | HTTP, Files |
| internal | A path | get, post, put, patch, delete | Internal messaging |
| sse | A path | subscribe | Bus |
| mail | An address, like support@, reply+{ticket : token}@example.com, or the catch-all "*@" | receive | Mail, Domains |
| mcp | A tool name, or a resource URI | tool, resource | MCP |
| timer | A timer name | none; a timer's fields sit directly under its name | Time |

Verbs like upload, subscribe, receive, tool, and resource are manifest verbs rather than HTTP methods: each is a promise about how the host handles that kind of request.

### Fields every route can have

| field | type | default | meaning |
| --- | --- | --- | --- |
| name | string | required | Unique within the box; names the generated code. |
| signal | integer (int32) | assigned by tooling | Links the route between host and guest. |
| response | "text", "markdown", "html", "empty", "json", "json:$Type", or "asset" | "text" | What the route answers with; asset streams a stored file without running the box. |
| template | string | none | A template name, to render a json response as HTML for browsers. |
| requirements | array, in disjunctive normal form | none | Who may call it, by grant roles. Present at all means the caller must be a user; an empty list means any signed-in user. |
| public | boolean | false | Opts out of requirements; refused alongside them. |
| queue | object | host defaults | max-depth, max-wait-ms, and overflow for when instances are busy. |
| grantable | object | none | options and to: the roles this route can grant. |
| revocable | object | none | options, to, and allow-self-revoke: the roles this route can take away. |
| shadow-calls | array of string | none | External services this route may call while shadowing. |

| field | applies to | type | meaning |
| --- | --- | --- | --- |

| body | http post, put, patch, internal | "json:$Type", "text", or "binary" | The request body. |

| folder | http upload | string | Where uploaded files land in the object namespace, built from reserved identifiers and route parameters. |

| listing | http upload | boolean | Whether the box may list its folder, one folder at a time. |
| asset-path | http get with response asset | string | The stored file to serve in the object namespace, built from reserved identifiers and route parameters. |

## Data

Data lives at data.$provider.$strategy.

| field | type | meaning |
| --- | --- | --- |
| schema | string | The .schema file the strategy is built on: a partial set of the database's tables, pinned at one version. |
| database | string | The database name, which may substitute reserved identifiers, like tenant_{!tenant}, on any route, or path arguments, like tenant_{tenant_slug}, only on internal routes, where the checker flags it for review. |
| table | string | The table. |
| pattern | "by_id", "by_index", "query", "sql", or "by_timer" | The access pattern, a manifest query iterator, direct SQL, or a source only timers can read, as described in the queries and time designs. |
| id-is | string | For by_id, the reserved identifier or parameter that is the row's id, like {!user_id}. |
| index | string | For by_index, the index declared in the .schema. |
| index-is | string | For by_index, the value the index column must equal, from a reserved identifier or a route parameter, like id-is for by_id; the host stamps it on inserts and checks it on updates and patches. |
| limit | integer (int32) | For by_index and query, the page size. |
| sql | string | For query, the single parameterized SELECT. |
| params | object | For query, each parameter as an inline schema or a reserved identifier. |
| result | "json:$Type" | For query, the type of each row. |
| tables | object | For sql, the tables and columns dynamic SQL may touch, with their operations. |
| row-limit, step-budget | integer (int32) | For sql, the most rows and SQLite steps one statement may use. |
| read | boolean | Whether the strategy generates a read. |
| writes | object | The strategy's writes, each by name; each generates exactly one function, named after the strategy and the write. There is no "write": true. |
| writes.$name.kind | "insert", "update", "upsert", "patch", or "patch-except" | Insert, replace, or insert-or-replace a whole row; or change exactly the listed columns, or every column except the listed ones. |
| writes.$name.columns | array of string | For patch, the columns it changes; for patch-except, the columns it leaves alone. |
| timezone-field, active-field | string | For by_timer, the column holding each row's timezone, and the column saying whether the row takes part. |
| publish | string | The bus topic bumped when the strategy's writes commit. |

## External services and other boxes

External services live at external.$service.

| field | type | meaning |
| --- | --- | --- |
| openapi | string | The pinned OpenAPI document for the service. |
| capability | string | A host contract with its version, like send-email@1, in place of openapi. |
| provider | string | Which host adapter fulfills the capability, like amazon-ses; operators can change it without changing the box. |
| box | string | Another box: for internal routes in place of openapi, or alongside openapi to redirect a pinned OpenAPI service to an adapter box. |
| base | string | The service's base URL. |
| credentials | string | A key name, like keys/tenant/{!tenant}/ses. |
| shadow | "fail" or "allow" | Whether calls are made while shadowing; allow only for methods with no effect. |
| methods.$method | object | The methods the box may call, by operationId, capability method, or route name. |

Each method can declare:

| field | type | meaning |
| --- | --- | --- |
| require | object | Request fields pinned to values, removed from the generated structure. |
| budget.calls | integer (int32) | The most calls per request. |
| effect | "none", "outbox", or "immediate" | Whether the call changes the world, and when. |
| idempotency | string | Where the idempotency key is sent, like header/Idempotency-Key. |
| delivery | object | attempts, backoff-ms, and within-ms, for outbox delivery. |

## The secure context

The secure context is exactly the set of reserved identifiers: !tenant, !domain, !user_id, !email, !client_id, !host_identity, !sender, !to, !caller_box, !caller_route, and !request_id. Each one, and the only way it can be set, is defined in the reserved identifiers design, and there is no context field to declare more.

Every reserved identifier that a box can see is part of its signature, so it decides which requests may share an isolate, a cache entry, and an ETag.

## Reachability

| route kind | must declare | notes |
| --- | --- | --- |
| http, sse, static, rewrite | requirements or "public": true | Neither is refused, and both is refused. |
| mcp | requirements | MCP is never public. |
| mail | "public": true | Senders aren't signed-in users, so mail routes are public, protected by verified sender claims and signed tokens in the address. |
| internal | callers, and optionally requirements | Never reachable from outside. |
| timer | nothing | Only the host ever calls a timer. |

## The invariants

- **A manifest has exactly one of box or config.** Configs can only declare what the host can do by itself.
- **Every field obeys one naming rule and one type vocabulary.** Hyphens for the platform, underscores for names, OpenAPI for types.
- **Every reachable thing says who can reach it.** Through requirements, public, or callers, and timers only by the host.
- **Every deployed manifest is complete.** Defaults and pins are written into it at deploy time, so what was approved is exactly what runs.
- **This document is the reference.** Where it and another design disagree about a field, this one wins, and the other gets fixed.

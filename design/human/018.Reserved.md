# Reserved Identifiers

Some values are too important to come from anywhere but the host. Who the caller is, which tenant a request belongs to, and which agent is acting can't be chosen by a caller, typed into a URL, or declared by a manifest, because every scope and every permission in the design rests on them. These are reserved identifiers, and they are always written with a leading "!", like {!tenant} and {!user_id}, so that anyone reading a manifest can tell at a glance which values the host vouches for.

## The convention

A manifest substitutes values with braces, and there are exactly three forms:

| form | example | where the value comes from |
| --- | --- | --- |
| {name} | {project_id} | A route parameter, a query parameter, or a field a timer provides. Something the request or the data carries, which the host checks against its type but doesn't vouch for. |
| {!name} | {!tenant} | A reserved identifier, set only by the host after it has resolved who and where the request is. |
| {name*} | {rest*} | The tail of a path, in rewrite patterns only, as described in the configs design. |

The "!" is the whole convention. A value without it was chosen by someone outside the host, so the design's rules about caller-chosen values apply to it; a value with it was set by the host, so it can be used anywhere a scope needs to be trusted. No route parameter, query parameter, timer field, or anything else a manifest names may start with "!", and no reserved name may be declared, shadowed, or overridden.

## The reserved identifiers

| identifier | set by | how it is set | meaning |
| --- | --- | --- | --- |
| !tenant | Domains | From the domain registry, for the domain the request arrived on | The tenant the domain provides. |
| !domain | Domains | From the domain registry | The primary domain the request arrived on. |
| !user_id | Identity | After identity resolution | The signed-in person, within the domain's realm. |
| !email | Identity | After identity resolution | The signed-in person's verified email address. |
| !client_id | Identity | After identity resolution, for agent tokens | The agent acting for the person, when there is one. |
| !host_identity | Identity | After identity resolution, for host operators | Whether the caller signed in as a host operator, as described in the identity design. |
| !sender | Mail | After SPF, DKIM, and DMARC alignment | The verified sender of an inbound message. |
| !to | Mail | From the SMTP envelope, once the address matches a registered, mail-enabled domain | The address an inbound message was delivered to, which catch-all routes use to file it. |
| !caller_box, !caller_route | Internal messaging | When one box calls another | The box and route that made an internal call. |
| !request_id | Host | When the request arrives | The id that ties a request to everything it causes, as in the operating panel's access log. |

Each identifier is only present when it means something: a public request has no !user_id, a timer has no !domain unless it set a tenant, and only an internal call has !caller_box. A route whose substitutions need a reserved identifier that isn't present is refused by the checker when it can tell ahead of time, and fails with a 500 at runtime when it can't.

## How each one can be set

The point of reserving an identifier is that there is exactly one way to set it, and none of them involve trusting the caller.

- **!tenant and !domain** come from the domain registry, for the domain a request arrived on. Internal calls carry them across from the caller. A data-driven timer route can set them only by naming a field of its source that holds a tenant, with tenant-field, and the host looks that value up in the registry before setting !tenant, so a timer can't invent a tenant that doesn't exist. Nothing else can set them, so a request on bobsplumbing.com can never act as another tenant.
- **!user_id, !email, !client_id, and !host_identity** come from the identity service, after it has verified a session or token. Internal calls carry them across. Timers never have them, so a timer can act about a person, through data, but never as them.
- **!sender** comes from the mail pipeline, only for senders that pass alignment.
- **!to** comes from the mail pipeline, from the envelope's recipient, only once that address belongs to a registered, mail-enabled domain. It says where a message arrived, not who may read it, so reading an inbox is still scoped by {!user_id}.
- **!caller_box and !caller_route** come from the host when it routes an internal call.
- **!request_id** comes from the host for every request.

## The invariants

- **Reserved identifiers start with "!".** Nothing else may.
- **Only the host sets a reserved identifier.** Each one has exactly one way to be set, listed above.
- **Reserved names can't be declared or shadowed.** No parameter, field, or role may take one.
- **A "!" means trusted, and no "!" means caller-chosen.** The checker applies the rules for caller-chosen values to everything without one.

# Language Targets

The launch goal to play with is having code generators for C and Rust at launch. We do C because C is easy to embed in other languages, and we do Rust because Rust has great WASM support built in.

Every generator is versioned, like c@1 or rust@1, and a box pins the version it was built with, as described in the stability design. Every generator reads the same manifest and types document and produces the same interface: the reactor exports, the route functions, the data and file functions, and the structures from the types document. C is the reference, since the C header is the boundary written down, and every other language is judged by how faithfully and cheaply it wraps it.

## The plan, per language

| language | when | how | consequences |
| --- | --- | --- | --- |
| C | Launch | The generator writes a header, as in every design document so far. | The smallest modules and the fastest start, which matters most for solo boxes that start an isolate per request. Memory bugs are the box's problem, contained by WASM, but they show up as errors. It is the honest measure of copy overhead, as the manifest design intended. |
| Rust | Launch | The generator writes a crate that wraps the C interface in safe types: borrowed slices instead of pointers and lengths, enums for signals, and Result for status codes. Boxes build for wasm32 as a reactor. | Memory safety inside the box, nearly C's size and speed, and the toolchain agents already use to compile WASM. Compile times are slower, and generated wrappers must never allocate behind the box's back. |
| C++ | Free with C | Uses the C header directly. | Nothing new to maintain. Exceptions and heavy standard library use make modules bigger, so boxes should keep to a small subset. |
| Zig | Soon after launch | Imports the C header directly through Zig's C interop. | Almost free to support, with C-like size and better safety checks. A smaller community means agents are less fluent in it. |
| Go | Later | TinyGo, with generated bindings over the C interface. | Familiar to many developers, but a garbage collector inside the box means bigger modules and slower starts, which push Go boxes towards the shared lifecycle. Some of the standard library doesn't work under TinyGo. |
| AssemblyScript | Later | Generated bindings over the C interface. | Friendly to TypeScript developers with small modules, but it is its own language that only looks like TypeScript, so agents and libraries are both thinner. |
| JavaScript and TypeScript | Later, as its own box type | A JavaScript box running in V8, as the introduction anticipates, with generated TypeScript types instead of compiled bindings. | The largest pool of developers and agents, and the fastest way to write a page. It is a different isolate type with different costs, so it needs its own measurements before it is offered, and cold starts favor the shared lifecycle. |
| Python | Exploratory | Compiling an interpreter and the program to WASM, with generated bindings. | Agents love writing it, but modules are large and starts are slow, so it fits shared boxes that do heavy work, not solo boxes that answer quickly. |

## How more languages arrive

Writing a generator per language doesn't scale forever. The longer-term path is to describe the interface once in the WebAssembly Component Model's interface language and let its tooling produce bindings for many languages, with the C header and the Rust crate as the first two outputs. The rule stays the same either way: a language is only supported when its generated code passes the same examples and the same tests as C, and when its cost to start and run a box has been measured and published in the operating panel.

## Consequences that apply to every language

- **The manifest doesn't change with the language.** A box's shape is its manifest, so rewriting a box in another language is a new version with the same shape, and the checker can confirm that nothing about its perimeter moved.
- **Start time shapes the lifecycle.** Languages with large runtimes cost more per isolate, so the cheaper they are to keep warm, the more they lean towards "shared." The checker can warn when a slow-starting language is paired with "solo" and a tight timeout-ms.
- **Generated code is part of the trusted surface.** A bug in a generator is a bug in every box written in that language, so generators are tested as seriously as the host.
- **Agents pick the language.** The platform doesn't care which language produced a module, as long as its manifest is honest, so the language an agent writes best is usually the right one.

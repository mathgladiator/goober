# Box flags

> Status: machine-authored, built 2026-10-30. The decision is the human's (§ 1).

A site's data engineer asked for runtime flags, so that freezing a box (no new orders while
data moves, say) needn't mean promoting a twin version. On 2026-10-30 the human chose flags in
the ABI: "flag_set {box, flag, value, reason} (audited; a changing tool), flag_list; boxes call
goober_flag(name) and get a string or nothing. Flags are per box and tenant, a short closed set
the manifest declares, so review sees every switch."

## 1. Declared in the manifest

```json
"flags": {
  "frozen": {"default": "false", "values": ["false", "true"], "about": "No new orders while true."},
  "banner": {"default": ""}
}
```

| field | meaning |
| --- | --- |
| `default` | Required. A string of at most 200 bytes, on one line: what the box reads until an operator sets it. |
| `values` | Optional. 1 to 20 strings: the only values `flag_set` accepts. The default must be one of them. |
| `about` | Optional. At most 300 bytes: what the switch does, shown by `flag_list` and the panel. |

Names match `[a-z][a-z0-9_]*`; at most 32 flags a box. The set is closed: a box can read only
the flags its manifest names, so a version's review shows every switch it has.

## 2. Read by the box

```
goober_flag(name_ptr i32, name_len i32) -> i32
```

The value goes into the result buffer, read with `goober_result_read`, and the call answers its
length (0 for an empty string). It answers -1 when the manifest declares no such flag, or a
pointer is bad. In Rust, `goober::flag("frozen") -> Option<String>`.

It is an additive import within goober-abi@1, as `goober_lib` was (831): a box that doesn't
import it is unchanged.

A value the manifest's `values` no longer allow reads as the default. Every flag a call read,
with its value, goes into that call's access log line (`"flags": {"frozen": "true"}`), so a
replay knows what the box saw.

## 3. Set by operators

- **`flag_set {tenant, box, flag, value, reason}`.** A changing tool: it waits for approval
  when an agent's approvals are on (035), and is scoped by tenant (030). Refused for a box
  that isn't active or doesn't serve the tenant, a flag the active version doesn't declare, a
  value outside `values`, a value over 200 bytes or with a line break, and an empty reason.
  The next call of the box sees the new value; no version, deploy, or restart.
- **`flag_list {tenant, box?}`.** A read tool, in the panel's list: each active box serving
  the tenant, every declared flag with its current value, default, values, about, and who set
  it, when, and why. Flags set but no longer declared are listed under `retired`, with their
  last value; they are kept, never read.
- **Kept.** Values live in `storage/flags/$tenant/$box.json`, written through the host WAL:
  durable, in the nightly and the increments (019), and outside anything a box can write.
- **Seen.** Each flip is a `flag` row in the change log, with the file before and after, and an
  `flag.set` line in the audit log (032) with the value, the value before, and the reason.
- **The panel.** A box's page has a Flags card: each tenant's flags, their values, and who
  flipped them.

## 4. What flags are not

Not per-person or per-row state: that belongs in the box's database. Not secrets: values are
plain, in the change log. Not a way for a box to change its own behavior: no box can set a
flag.

## 5. Tests

- `manifest_test`: the shape, names, defaults, values, the default being one of the values,
  and at most 32.
- `host_test` `HostFlags`, with a WAT box:
  - reading the default, then the value after `flag_set` on the next call, with no new
    version;
  - -1 for an undeclared name;
  - refusals: a value outside `values`, an undeclared flag, a missing reason;
  - `flag_list`, the change log row, the audit line, and the access log's `flags`;
  - the value after a restart.

## 3. Fixed in the first loop

### 3.1 Security

- **S1 (high). Beta's operator dropped production boxes at once.** Beta's scope refused
  `box_drop` only for a live box. A disabled or stored-dark production box passed scope (judged
  by `in_code`), and `drop_approval` let any beta operator's drop run without the owner, deleting
  every version. Any agent could become beta's operator by sending its usual token with the
  beta-ops Host. Now a version first stored for beta says so in its life record (`channel:
  "beta"`), and beta's operator drops at once only a box that is in beta's slot, not live, not
  disabled, and whose every version was first stored for beta and never live; or a beta tenant's
  database. Any other drop it asks for waits for an owner, as anyone's does.
- **S2 (high). The approvals switch was skipped through beta-ops.** Through beta-ops an agent's
  name became `beta:<name>`, which matched no switch, so an agent an owner had put under approvals
  ran its changes unheld by changing its Host header. `approvals_on` now unwraps `beta:`.
- **S3 (medium). Beta could open production's data.** `DataStrategy::tenant_for` mapped a pinned
  tenant to its beta, but fell back to the production tenant when it had none, against 053's
  "beta never opens production's data". It now answers `kNoBetaTenant` + the name, which
  `Session::open_database` refuses ("tenant x has no beta") and no other path can open.
- **S4 (medium). `beta_mail_send` had no scope check.** An operator focused on one tenant could
  inject mail, its From trusted, into any beta. It now refuses a beta whose domain's tenant is
  outside the caller's focus, in the tool and the panel alike.
- **S5 (low). Beta's operator read production's box logs.** Box log lines now name their tenant,
  and `box_logs` shows a focused operator (beta's included) only its tenants' lines.

### 3.2 Correctness

- **C1 (medium). Beta blocked production deploys.** `activate` rebuilt every table, beta's
  included, so a beta version claiming a route refused a production version that added it. Now
  production wins: the beta version in its way is cleared from its slot, and production goes
  live. A reload that names a new beta domain leaves out only the beta versions that conflict.
- **C2 (low). The controller could bring a stopped split back.** `split_tick` read a split, then
  wrote it, unaware of a `split_stop` or `split_set` in between. A Host lock (`split_change_mu_`)
  now spans each read, judgment, and write, and `BoxRegistry::split_set` tells starting from
  changing under its own lock, refusing a change to a split that ended meanwhile and a second
  start.
- **C3 (low).** A split a new live version or a disable ends now keeps its record as
  `split-last` (outcome `ended`), as 052 § 4 said.
- **C4 (low).** The drop checks count beta versions: a database a beta version binds (a pinned
  tenant mapped to its beta included) and a box a beta version calls are blocked, and a box only
  in beta shows state `beta`.

### 3.3 Performance

- **P1 (low). Beta's mailbox had no byte bound.** Now `limits.beta-mail-bytes` (64 MiB a beta
  tenant) besides 2000 messages and 30 days, text and html cut at 256 KiB, and a small row beside
  each message that `beta_mail_list` reads. The limits check reports `beta-mail`.
- **P2 (low). Skill searches stalled `/goober/ready`.** The library is now read under a shared
  lock, its totals are atomic, and a body's count stops at the 5 it can score.
- **P3 (low).** The Cleanup view no longer refreshes every 15 seconds, since it counts every
  table's rows.
- **P4 (low).** The beta-tenant and alias maps are read through a per-thread copy refreshed when
  their generation moves, instead of an `atomic<shared_ptr>` load per call.

## 4. Fixed in the second loop

### 4.1 Security

- **S6 (high, latent). A grant from beta-ops wasn't bound to beta.** Beta's scope came only from
  the Host header, so a token an agent used on beta-ops worked with its person's full rights on
  any other domain. For bearer tokens that is as designed (a person's token is theirs; a token
  focused on beta tenants, or `host:beta` alone, is beta's anywhere). For operator OAuth, beta-ops
  doesn't serve the issuer yet (§ 6, decision 1), so no OAuth agent reaches beta-ops today; when
  one does, its client is recorded in `storage/operations/beta-clients.json` on registration or on
  taking a token through beta-ops, and its agent is `beta:` on every domain from then on.
- **S7 (medium; from 030, reachable through beta). Box scope judged the wrong version.** For a
  box not live, scope looked at `versions().back()`, which is sorted by hash, and an upload over a
  disabled box looked at nothing. A focused operator could take over another tenant's disabled
  box's name, or read a dark box's versions by storing one that sorted last. Scope now judges a
  disabled box by the version it would enable, and a box only stored by every version it has.
- **S8 (low). Beta's drop raced a promotion.** The check ran before the drop; the registry now
  checks again under its lock that the box isn't live or disabled.
- **S9 (low).** The same bytes stored for production after beta kept beta's mark; a store for
  production now erases it.
- **S10 (low).** `beta_status` showed every tenant's boxes to beta's operator; it now shows a
  focused operator only its own sites and boxes.
- **S11 (low).** The panel hid an operator's beta-ops agents' held requests; it shows them.
- **S12 (low; from 041/030).** `schema_put` checked a schema's own name, not the schema it
  `follows`, so a focused operator could take the one "follows" slot of another tenant's schema.
  Both are checked now.

### 4.2 Correctness

- **C5 (medium). A cut beta message could become unreadable.** The 256 KiB and 160-byte cuts
  could split a UTF-8 character, which the JSON parser then refused. Both cut at a character
  boundary now.
- **C6 (low).** A strategy pinned to a beta tenant itself was turned into "no beta"; it opens
  that tenant again.
- **C7 (low).** A split's promotion by the controller could undo a disable or a newer live
  version made in between; `promote(..., from_split)` now refuses unless the split still runs.
- **C8 (low).** A dry run, a store, or an upload didn't say that going live would clear another
  box's beta version; it says so in its warnings.
- **C9 (low).** When production's own boxes conflict on a beta domain (a box names it outright),
  a reload or a restart published half-built tables; production now keeps its tables and beta
  gets none of its own, said in the log and the load's warnings.
- **C10 (low).** A box pinned to a tenant never fired its timers on beta; it fires them for that
  tenant's beta, as `tenant_for` opens it.
- **C11 (low).** `beta_status` now lists a beta version kept in its slot but not served
  ("not served: it conflicts on a beta domain").

## 5. Not fixed, and why

- **`fit_beta` builds the tables once per beta version** when production conflicts with one, and
  `load_all` does a trial build per beta version at every start: 1.7 s at 80 boxes with beta
  versions, under the registry's lock (requests aren't blocked; uploads and the controller are).
  A conflict is rare and a host has a handful of boxes; the fix (build production once, add beta
  versions incrementally) waits for a host that needs it.
- **Skill writes can starve behind searches.** libstdc++'s `shared_mutex` prefers readers: in
  process, 8 back-to-back searchers held a put off for 9 s. Over MCP each agent gets 10 calls a
  second and 2 running, so it would take about 50 agents searching flat out. A copy-on-write
  snapshot would remove it.
- **Each beta capture scans its mailbox** (a directory listing, a sort, up to 2000 sizes, two
  writes): 2.8 ms at 2000 messages on tmpfs, plus fsyncs on a real disk, on the box's thread.
  An in-memory index per tenant would remove it.
- **`box_drop_check` is O(boxes²)** and reads every controls file once per box; `cleanup_report`
  runs it per box. Fine at a handful of boxes.
- **The skills index takes about 4.8 times the skills' bytes** in memory (77 MiB for 16 MiB).
- **A split's `history` grows** by one entry a step or manual change; a split has few.
- **A drop's snapshot skips the snapshot budget**, by design (051: kept until a person deletes
  it).
- **Tests not written:** timers, identity events, outbox results, and internal calls on beta
  versions; a box MCP tool split by user; the p99 guardrail; `split_set {mode: "ladder"}`
  resuming; splits skipped on beta domains; the access log's `split` field; `split_start` held
  under approvals; the controller and the tools serialized; `Session::open_database`'s "has no
  beta" message (only `tenant_for` is tested); the panel listing beta agents' requests; a beta
  caller blocking a drop. Each is a path the reviewers read and found sound or fixed.
- **Small code debts:** `text_of` copied into five new files beside `text_arg` and `arg_text`;
  the manifest package's two process-wide maps (now written down in its QUALITY.md).

## 6. Decisions for the human

1. **OAuth agents on beta-ops.** beta-ops serves the operator MCP but not the operator OAuth
   issuer (its well-known metadata, `/oauth/operator/*`, and the host sign-in), so Grok, which
   signs in only by OAuth, can't connect to beta-ops. Today an agent is held to beta by focusing
   its person or token on beta tenants alone, or by `host:beta`. Options: (a) serve the issuer on
   beta-ops, every client that registers or takes tokens there bound to beta everywhere (the
   binding is built and tested); (b) leave it, and hold agents to beta by scope. Recommendation:
   **(a)**, since 053 § 6 promised "a token or OAuth grant from beta-ops is focused on beta
   tenants", and you want Grok's engineering to work only on beta.
2. **Who applies a promotion.** `changeset_apply` of a promotion change set runs for any operator
   not focused on tenants (held only when that agent's approvals are on); the panel's Promote view
   is the owner's alone. You said "I'll take control of promotion and migration". Options: (a)
   as built; (b) a promotion change set always waits for an owner, as drops do.
   Recommendation: **(b)**.
3. **Production clears a beta version in its way for good.** When a production version goes
   live over a conflicting beta version, that box's beta slot is deleted (the version stays
   stored). Options: (a) as built, said in the upload's warnings and the log; (b) keep the slot
   and leave it unserved until beta changes. Recommendation: **(a)**: it keeps memory and disk
   the same and tells whoever deployed.
4. **Beta's full mailbox and the limits warning.** The `beta-mail` row sits near 100% once a
   mailbox fills, which is its normal state (the oldest go). Options: keep it in the warnings, or
   report it without warning. Recommendation: **report without warning**.
5. **Which "train" (052 § 9)** and 052's other open decisions, 050's five, and 049's six still
   wait.

## 8. Checked and found sound

- **Drops.** A held drop needs an owner and the typed name; the approval is claimed before it
  runs, and the checks run again then; a dry run is a read call, however `dry_run` is spelled; a
  change set can't carry a drop; the panel's `write/drop` is an owner's, focused on every tenant.
- **Beta's isolation.** Beta-ops refuses every panel write but injecting mail; `host:beta` can't
  decide approvals, set scopes, lift blocks, drop, or promote; production's boxes are staged only
  with channel "beta"; disable, enable, restore, splits, and change set apply and rollback are
  refused; kTenant tools stay on beta tenants; system keys are refused; captured mail never
  reaches the mailer; the MTA hook refuses mail to beta; reply tokens are bound to tenant, box,
  and route; services from beta need `"beta": "allow"` and an effect of none; push is captured.
- **Data.** No path creates a file or directory named with `kNoBetaTenant`: every caller goes
  through `Databases::exists` or `open`, or `open_database`'s refusal.
- **Locks.** The order is `split_change_mu_`, then the registry's `mu_`, then `snapshot_mu_`;
  `splits_mu_` is taken last and alone; no registry callback takes a split lock.
- **Splits.** Never on beta domains; candidates must answer the same routes and bind the same
  data; a restart resumes a split with its salt; the candidate is kept from pruning.
- **Skills.** Names and roles are `[a-z0-9-]`; front matter is written JSON-quoted; writes are
  host-wide, so beta can't write them; the panel draws markdown as text, links http(s) only.
- **The panel.** Host data is placed as text or SVG text; every write checks its content type
  and exact Origin; captured HTML shows in a `<pre>`.
- **The request path.** Without a split nothing new runs; with one, about 1 to 4 µs; the beta
  tables are built at activation, never per request.

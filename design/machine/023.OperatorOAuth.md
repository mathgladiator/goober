# 023. Operator OAuth: agents reach the operator tools by signing in

Status: built, at the human's request on 2026-10-28. Grok's MCP connector offers OAuth or no
authentication, with no place to paste a bearer token, so it couldn't reach
`/goober-operations-mcp`. The human chose operator OAuth over a token in the URL. This extends
`design/machine/009.OAuth.md` (the site realms' OAuth) to the host realm, `_host`.

## 1. Two issuers on every domain

| issuer | realm | signs in | protects |
| --- | --- | --- | --- |
| `https://$domain` | the domain's tenant | the site's people | `/mcp` (the site's box tools) |
| `https://$domain/oauth/operator` | `_host` | addresses in `identity.operators` | `/goober-operations-mcp` |

The operator issuer has the same endpoints as a site's, under its own path:
`/oauth/operator/authorize`, `/token`, `/revoke`, `/register`, `/device`, and
`/device/verify`. Its metadata (RFC 8414) is at
`/.well-known/oauth-authorization-server/oauth/operator`, and also at
`/oauth/operator/.well-known/oauth-authorization-server` and the `openid-configuration` names,
for clients that look there.

## 2. How a client finds it (MCP authorization, RFC 9728)

1. The client posts to `/goober-operations-mcp` and gets 401 with
   `WWW-Authenticate: Bearer resource_metadata="https://$domain/.well-known/oauth-protected-resource/goober-operations-mcp"`.
2. That document names the resource and `authorization_servers: ["https://$domain/oauth/operator"]`.
3. The client reads the issuer's metadata, registers itself (RFC 7591), and sends the browser
   to `/oauth/operator/authorize` with PKCE (S256).
4. Signed out, or signed in only as a person of the site, the browser goes to
   `/identity/sign-in/as-host`, where only an address in `identity.operators` gets a code.
5. The consent screen says the agent will act **as a host operator**, able to do everything the
   operator tools can do on every site, and, for a client that registered itself, that nobody
   has checked it. Allowing mails the operator (the `new-grant` template).
6. The code is exchanged at `/oauth/operator/token` for an hour-long access token and a
   rotating refresh token.

## 3. What the token is

- `bearer_operator` accepts, in order: the config's `operations.token`, a token from
  `goober-host token create`, then an access token of the `_host` realm whose person is still
  in `identity.operators` with a role. Removing the address from the config ends its tokens'
  access at once. The access log names the operator as `oauth:$email:$client_id`.
- The token works only on `/goober-operations-mcp`: the site's `/mcp` checks the tenant realm
  and refuses it.
- Revoking (`/oauth/operator/revoke`) ends the grant, and refresh reuse revokes it, as in 009.

## 4. Limits and risks

- A client built to the older MCP authorization (2025-03-26), which looks for authorization
  metadata only at the origin's root, finds the site's issuer instead. It would sign a person
  in to the site, and the operator endpoint would refuse that token. If Grok behaves that way,
  the fix is a separate origin for operations (a subdomain), recorded here as the next step.
- An operator's grant is as strong as the operator: it can change every site, so the consent
  screen says so, and the mail says it happened.
- Not built: a page listing operator grants (the host realm has no account page yet), scopes
  narrower than "everything".

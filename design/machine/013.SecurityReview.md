# Security Review, 2026-10-26

> Status: machine-authored. Three read-only reviewers each took one part of `host-src/`
> (identity, OAuth, and the screens; content, rendering, and files; the box boundary, SQL,
> operators, and the HTTP server) and reported confirmed findings with attack scenarios,
> suspicions, and what they found sound. This records every finding and what became of
> it. Fixes landed in commits f4db06f, 921e313, and the one that adds this file, and each
> has a test. Nothing here has had an outside review; this is the house checking itself.

## Fixed

### Found later by fuzzing

The fuzz package (`host-src/packages/fuzz`, `just fuzz`) added a seeded mutation fuzzer for
every parser and a property test of the SQL authorizer. Every parser ran clean, and so did the
whole suite under AddressSanitizer and UndefinedBehaviorSanitizer. The property test found two
real holes:

| # | severity | finding | fix |
| --- | --- | --- | --- |
| F1 | high | `INSERT INTO open SELECT * FROM secret` copied a table the strategy had no grant on. SQLite's transfer optimization copies raw rows without asking the authorizer about the columns it reads. | Before a box's statement runs, the host walks its compiled program: every table or index it opens must belong to a table the strategy grants something on, and a program that copies raw rows (RowData) may only read tables the strategy reads in full. This check doesn't depend on the authorizer. |
| F2 | medium | A write SQLite interrupted (a runaway recursive DELETE past the step budget), or `INSERT OR ROLLBACK`, rolled back the request's whole transaction. Later statements then committed one at a time, so a request that answered 5xx could still leave writes behind. | `OR ROLLBACK` is refused like REPLACE. A session that sees SQLite leave its transaction refuses every later statement and fails its commit, so the request fails and nothing of it lands. |

## Checked and found sound

The reviewers traced these and found nothing:

- **Box boundary.** Pointer checks, imports, header rules, and hiding credentials from boxes.
- **SQL authorizer.** It denies PRAGMA (including the `pragma_*` functions), ATTACH, DDL, transactions, and the host's and SQLite's tables. It doesn't trust CTE names, it authorizes RETURNING reads, and it allows only pure functions.
- **Tenant databases.** No cross-tenant paths.
- **WAL and stores.** Path checks everywhere.
- **Operator tokens.** Random, hashed, compared in constant time, and kept out of logs.
- **The validator.** No parser differential.
- **The Beast parser.** Header limits and read deadlines.
- **Agents.** Agent tokens are refused where they should be.
- **Identity.** Host and tenant identities stay apart; no cross-realm tokens; PKCE, codes, and refresh rotation behave; no races under the realm locks.
- **Screens and sessions.** Redirect URI matching; escaping and framing on the screens; no session fixation; cookie attributes.
- **Logs.** No token reaches a log.
- **Markdown and Mustache.** The renderer escapes raw HTML and filters URL schemes; Mustache escapes everything but the host's `body`.
- **Content and attachments.** Path normalization and private segments, and draft and requirement checks before every other way of reaching a page. Attachments are sniffed, `nosniff`, and SVG and PDF are downloads under a sandbox CSP. The multipart parser runs in linear time.

## The second review (2026-10-30)

Three reviewers (agents) read the week's work: speaking HTTP (034), the operator surfaces
(030, 035, 028), and invites, logs, and the content kit (029, 032, 031, 027). Every finding was
checked against the code before it was fixed; fixes are in commits f12ef9c, 5194b01, and
d1417d7, each with tests. The fuzz suite gained specs, include markers, sealed values, and
OAuth 1.0a URLs, which found a second spelling of sealed values and a null `memcpy`.

**Fixed, by severity:**
- **High.**
  - A box could send a person's sealed credential to any URL. Sealed values are now bound to
    their origin and owner.
  - `mail_template_preview`, a read tool, sent mail.
  - A focused agent could set system keys, reach another tenant's database through a pinned
    strategy, replace another tenant's box, or promote an out-of-scope version.
  - Batched calls were never audited.
  - `page_lint` could be aimed at internal addresses (SSRF).
- **Medium.**
  - Unbounded waits from Retry-After, and polling holding a service's lane.
  - A spec path that looped forever; Strava's doubled basePath; pin collisions.
  - Paste checks that could be skipped.
  - Revoked agents' requests ran with old roles; secrets were kept in held requests; requests
    could stay `running` for ever.
  - `current_operator()` leaked on exceptions.
  - Regex and SQL without bounds.
  - Consent bypassed with plus-addressing and gmail dots, and lists re-asked people who left.
  - Addresses and capability links in logs and stats.
- **Low.**
  - Multipart file names, OAuth 1.0a decoding, and refresh replies.
  - A torn write breaking the log chain, and a wrong `chain_before` in rotation manifests.
  - Origins taken from the raw Host header, and XML that was ill-formed for feeds.
  - Owner switches an operator could clear, and limits applied before filtering.

**Not fixed, and why:**
- **The panel's waiting list loads every argument.** It still loads each held call's arguments,
  up to 50 per agent at 1 MiB each, so a misbehaving agent can make the page heavy. That
  agent's switch is the remedy; lazy loading can come later.
- **Operator names split on the last `:`.** A client id holding `:` would map to an unknown
  scope key, and an unknown key means all tenants. Every client id is host-minted (`dyn_<hex>`)
  or set in config, so this can't happen today.
- **`fetch_self` needs a loopback listener.** It fails when the host listens on one specific
  non-loopback address. It fails closed, and production listens on 127.0.0.1 behind Caddy.
- **`outreach_opt_out` is never called.** So the `opted_out` state can't happen. That state
  isn't needed while blocks cover it.
- **The consent log is a plain table.** It isn't chained like the logs (032); its rows are
  written in the same transaction as the state they record.

## The third review (2026-10-30, afternoon)

Three more reviewers read identity and OAuth, the box boundary, and the operational edges
(source builds, backups, mail in, deploy, push, the HTTP server). Each finding was checked
against the code before it was fixed, with a test.

**Fixed:**
- **High.**
  - Child processes (curl, tar, the build sandbox) inherited the host's sockets, so a
    build script could accept the site's connections. Children now get only fds 0 to 2
    (`closefrom`), and the listener and connections are close-on-exec.
  - One SQL statement could allocate gigabytes: 2,000 columns of 4 MiB values, checked only
    after the row was built. Now at most 128 columns, the 8 MiB result cap is checked per
    column, and SQLite has a 1.5 GiB hard heap limit.
  - An RRULE expansion had no work bound. BY lists are de-duplicated, an expansion stops
    after 2 million candidate times, and the request's deadline is checked between library
    calls.
  - Box headers had no size cap, so a box could make the host copy gigabytes. Now 8 KiB a
    header, 32 KiB in all, and 256 bytes of content type. SQL params and call requests are
    capped at 8 MiB and library arguments at 1 MiB, checked before copying.
- **Medium.**
  - A tenant page's plain form could Allow an operator grant. The Allow now needs a token that
    only the consent page makes.
  - The operator issuer's endpoints had no rate limits of their own; they now share the
    issuer's buckets. Self-registered clients are capped at 1000 a realm, without a prune on
    every registration.
  - Box randomness was predictable from the logged seed. It is now ChaCha20 keyed by a host
    secret.
  - `refresh`, `clear-site-data`, HSTS, and similar headers belong to the host now.
    `x-forwarded-*`, `forwarded`, `via`, and the real IP are hidden from boxes.
  - Encoded-word decoding was quadratic, so any sender on port 25 could reach it. It is now
    linear, and capped at 64 KiB.
  - A sandbox devbox could still send calls, pushes, and fetches out; every way out now
    refuses. URLs with user info are refused.
  - The mail hook's 51 MiB body limit applied before its token was checked; the token is now
    checked first. Caddy answers `/internal/*` with 404.
  - Builds had no resource limits. They now run under prlimit (8 GiB of address space, 2 GiB
    per file, 2048 processes), and a build won't start with under 2 GiB of disk free.
  - Source scope checks raced with commits, and missed what a commit wrote. A deploy is now
    pinned to a revision before the check, and a commit is checked as the project will be
    after it.
- **Low.**
  - A raced refresh could be replayed without limit; past six live tokens in a family it
    counts as reuse.
  - A wrong PKCE verifier didn't spend the code; now it does.
  - Agent tokens could be minted for addresses nobody had proved.
  - The invite MAC is compared in constant time, and accepting an invite needs a click.

**Not fixed, and why:**
- **Operator sign-in on tenant origins.** A script on a tenant page could still drive the
  operator consent screen; only serving `/oauth/operator/*` and host sign-in on the panel's
  origin closes that. That moves where Grok connects, so it waits for the human.
- **Lockout by wrong codes.** Anyone can lock an address out of email sign-in for a day with
  about 20 wrong codes, and a new code supersedes older ones. Binding codes to the browser
  that asked for them trades lockout for guessing odds, and that trade waits for the human. An
  operator locked out still has `goober-host token create` on the server.
- **Internal callers named but not yet uploaded.** A box's `callers` can name a box that
  doesn't exist yet, and anyone who may create boxes could claim that name. Operator scope
  limits who can.
- **Write locks held across outbound calls.** A request can hold its database's write lock
  through a slow `goober_call`; others on that database wait up to 5 seconds.

## The fourth review (2026-10-30, evening): security, quality, performance, reliability

Four reviewers, one per dimension, over two days of code, newest first: the bus and
subscriptions, the operations audit and deploy, approvals, and speaking HTTP.

- **High.**
  - **The deploy, as root, wrote through paths the host's user owns.** `panel_setup` copied
    `host.json` beside itself with `cp -p`, and the mail step `chown`ed and read
    `mail-hook.token`, all in the host's directory. A symlink planted there by the host's user
    (a compromised host) would have aimed root at `/etc/passwd` or `/etc/shadow`. Root now makes
    no write, chown, or read through a path in that directory: the host's user makes those
    copies, root reads the token as that user, and Stalwart's copy goes through root's own
    temporary file.
  - **A stream opened after `sse_stop` outlived the server it belonged to,** so the stop freed
    its session twice. Subscriptions now get 503 while the host stops, a stream admitted just
    before closes at once, and what's left is closed before the server goes.
  - **The panel's setup restarted the host after every check had run,** and didn't wait to
    see it come back. It must now be ready within a minute, or both files go back, the host
    restarts on them, and the deploy fails.
- **Medium.**
  - **Subscription groups ignored the domain and the agent.** Two domains of one tenant, or a
    person's browser and their agent, shared one answer; the box renders for each differently.
    The signature now holds everything the box is shown.
  - **A subscription showed the box any header it declared,** including the client's address
    (`x-forwarded-for`); those are now hidden as on HTTP routes. A subscribe route's plain GET
    skipped 037's status rules, so a box could make it an open redirect; it shares them now.
  - **Stream limits could be overshot** by a burst (counted when the stream opened, not when
    the request was admitted), and 4000 streams nearly filled the server's 4096 connections.
    A slot is now taken at admission, and the limits are 2000 for the host and 500 a tenant.
  - **A subscription's evaluation could take its database's write lock** (a strategy that may
    write began `IMMEDIATE`); read-only sessions now begin deferred.
  - **Approvals kept secrets** when a request expired (only `key_set`'s value was hidden), was
    refused because its agent can't sign in, or was interrupted. Every final state now keeps
    the shown copy only, and the store zeroes what it deletes.
  - **Hardening that can't apply (a container's read-only `/proc/sys/net`) aborted the deploy**
    between the restart and the rollback check; it now says so and carries on.
- **Performance.**
  - A log's rotation hashed up to 256 MiB under the writer's lock, on the request whose line
    crossed the day; every request waited. Rotation is renames now, and the hash waits for
    housekeeping. The writer keeps its file open.
  - Mail held the host's ledger lock across the provider's API call; a send is now counted
    first and the lock let go, and the ledger stays open.
  - One subscription answer was copied per subscriber; it's one shared string now. Bus
    eviction, stream counting, and stream close were linear; they're constant time.
  - The reply key was read from disk on every box call; it's read once.
- **Reliability.**
  - One exception in an evaluation froze its group; the group is now always let go.
  - Subscriptions scheduled on the wall clock; they use the monotonic one.
  - An approval whose result wasn't text stayed `running`; results of any shape are kept,
    and marking it done is retried.
  - A poll that didn't get through moved its job into the service's ordered lane, blocking it;
    it stays polling.
  - Tests of one binary raced each other's directories under `ctest -j`.

**Not fixed, and why:**
- **First install reads unit files from the host's directory as root.** `setup.sh` writes them
  there as the host's user moments before; no host code has run yet.
- **Partials are read and hashed per marker,** and operator scopes are read per call. Cheap at
  today's traffic.

# Progressive web apps

On 2026-10-29 the human asked that goober fully support PWAs, so that a whole domain, or a
part of one, can be its own installable app. They asked for an audit of the gaps, for the
gaps to be filled, and for this document of findings. For Web Push they chose OpenSSL's
libcrypto over hand-written P-256 or no push. This is built.

## 1. What a PWA needs, and what goober had

| need | before | now |
| --- | --- | --- |
| HTTPS | Caddy and HSTS in production; `localhost` is a secure context for development | unchanged |
| A web app manifest, linked from every page in the app | a tenant could hand-write one, but `.webmanifest` was served as octet-stream until earlier the same day, nothing linked it, and no template had a place for it | generated per app, linked by `<!--#include pwa-->` (§ 3) |
| A service worker, served as JavaScript, never redirected | static `.js` files worked | generated per app, with `Service-Worker-Allowed` (§ 4) |
| A worker scope that covers the app | a content file can't send `Service-Worker-Allowed`, so a worker controls only its own directory | the host's worker lives under `/goober/pwa/$app/` and is allowed the app's scope |
| A scope's own URL in scope | `/shop` and `/shop/` both answer 200, with no redirect out of scope | unchanged; `/shop` counts as in the scope `/shop/` (§ 2) |
| Registering the worker | templated pages' CSP is `script-src 'self'`, so no inline `navigator.serviceWorker.register` | an external `register.js` per app |
| Working offline | nothing | network-first pages with a fallback page, stale-while-revalidate assets (§ 4) |
| Updates reaching installed copies | every file is `no-cache` with an ETag | the worker's text changes with its definition and with the host build, so browsers update it |
| Icons, including iOS | attachments and content files are typed by their bytes or extension | the manifest's icons, plus `apple-touch-icon`, `theme-color`, and the app-capable metas |
| Several apps on one domain | n/a | each app has a scope, and the longest scope that fits a page wins |
| Push notifications | none, and no P-256 crypto in the host | Web Push: VAPID (RFC 8292), aes128gcm (RFC 8291), subscriptions, a `push` service for boxes (§ 5) |
| Signed-in pages | `private, no-cache` | never stored by the host's worker (§ 4) |
| Box pages in an app | partials expand in box templates, and in raw HTML with `"includes": true` | the same, so a box page gets the app's tags |

## 2. An app

An app is a file in the tenant's tree, `_apps/$name.json`. It is never served by itself, and
it is written with `pwa_put`:

```json
{
  "scope": "/shop/",
  "manifest": {
    "name": "KC Meat Shop", "short_name": "Meat",
    "icons": [{"src": "/icons/192.png", "sizes": "192x192", "type": "image/png"},
              {"src": "/icons/512.png", "sizes": "512x512", "type": "image/png", "purpose": "any maskable"}],
    "theme_color": "#8b1e1e", "background_color": "#ffffff",
    "shortcuts": [{"name": "Orders", "url": "/shop/orders"}]
  },
  "worker": "host",
  "offline": {"fallback": "/shop/offline", "precache": ["/css/shop.css"]},
  "push": {"anonymous": false}
}
```

**`scope`** is `/` for the whole domain, or a path that ends in `/`.
- A scope never starts at one of the host's own paths (`/goober/`, `/identity/`, `/oauth/`,
  `/.well-known/`, `/mcp`, `/internal/`). It never has a segment starting with `_`.
- Two apps can't share a scope.
- A page belongs to the app whose scope it fits, the longest scope winning. A scope's own
  URL without its slash (`/shop`) fits it.

**`manifest`** holds the Web Application Manifest's members.
- A field it doesn't know is an error, so a typo can't hide. `scope` is the app's own field.
- The host fills in `scope`, `start_url` (the scope), `id` (the scope), and `display`
  (`standalone`).
- `start_url`, `id`, icons, and shortcuts are paths on the site, and `start_url` must be in
  scope.
- `pwa_put` warns when browsers won't offer install: no 192×192 or 512×512 icon, or no
  `short_name`.

**`worker`**:
- `host` (the default): § 4.
- `none`.
- `{"src": "/shop/sw.js"}`: the tenant's own worker, registered by the host's script. It must
  sit in the scope's directory or above, since content files don't send
  `Service-Worker-Allowed`.

**`offline.fallback`** is the page the host's worker shows when a page in scope is neither
reachable nor cached. **`offline.precache`** lists up to 200 paths fetched at install, beside
`start_url` and the fallback.

**`push`**: `true` (the default), `false`, or `{"anonymous": true}`, which lets signed-out
visitors subscribe too.

## 3. The tags

`<!--#include pwa-->` is a built-in partial (`design/machine/027.Partials.md`).
- **In scope**, it expands to the tags of the app that fits the request:
  - `<link rel="manifest">`;
  - `theme-color`;
  - `mobile-web-app-capable`, `apple-mobile-web-app-capable`, and
    `apple-mobile-web-app-title`;
  - `apple-touch-icon` (iOS reads its home-screen icon from the page): the 180-pixel icon,
    else the largest;
  - `<script src="/goober/pwa/$app/register.js" defer>`.
- **Out of scope**, it expands to nothing, and that is not a missing partial.
- **A tenant's own `_partials/pwa.html`** wins over the built-in.
- **The built-in base template** has the marker in its `<head>`. A tenant's own layout, a
  document, or a box template adds it where its head is.

## 4. What the host serves

All of it sits under `/goober/pwa/$app/`, a host-reserved prefix (041), so no tenant path is
taken.

| path | is |
| --- | --- |
| `manifest.webmanifest` | the manifest, `application/manifest+json`, with an ETag |
| `sw.js` | the host's worker, `text/javascript`, `no-cache`, `Service-Worker-Allowed: $scope` |
| `register.js` | registers the worker for the scope, and defines `window.goober.push` |
| `push` | GET: the VAPID public key. POST: subscribe. DELETE: unsubscribe (§ 5) |

**The host's worker.** Its configuration is the app's definition. Its version is the
definition's hash plus the host build, so either change makes browsers update it.
- **Install.** It fetches `start_url`, the fallback, and `precache` into its cache, each on
  its own, so one missing page can't stop the install.
- **Activate.** It drops its older caches, turns on navigation preload, and claims its pages.
- **Pages in scope** are network-first, kept when they may be kept. Offline, they come from
  the cache, then the fallback.
- **Assets** (styles, scripts, images, fonts, `/attachment/`) are stale-while-revalidate,
  same-origin only.
- **Never intercepted:** other methods than GET, other origins, and the host's own paths.
- **Never stored:** a response marked `private` or `no-store`. A person's signed-in pages stay
  off the device, so a shared phone keeps no one else's account.
- **Push events** show `{title, body, url, icon, badge, tag}`, the app's name standing in for
  a missing title. A tap focuses or opens `url`, same-origin only.
- **A renewed subscription** (`pushsubscriptionchange`) is re-sent to the host.

## 5. Push

### Keys

- **The host's VAPID key.** One P-256 key, made when the first app with push is served, and
  kept in the key store as `keys/system/vapid_private_key`.
- **The contact.** VAPID names the operator as `pwa.push-contact`. Without it, the contact is
  the mailer's address, else the public URL, else `postmaster@` the platform domain.

### Subscribing

The page calls `window.goober.push.subscribe(["orders"])` from a tap. It asks permission,
subscribes with the host's key, and posts the subscription to the host.

The host accepts a subscription only:
- as JSON;
- from the site's own origin;
- with an endpoint on a browser's push service (FCM, Mozilla, Apple, Windows), or on a host
  named in `pwa.push-hosts`;
- with keys of the right size.

The allowlist is what keeps a visitor from making the host post to an address of their
choosing. Delivery also goes only to a checked public address (security review S4-5).

Once accepted:
- **Who it belongs to.** A subscription is tied to the signed-in person. A signed-out visitor
  may subscribe only when the app says `anonymous`.
- **Limits.** A person keeps at most 20 subscriptions (the newest), and a subscription at most
  20 topics.
- **Removal.** Whoever holds an endpoint may remove it.
- **Where they live.** `storage/pwa/push.db`.

### A box sends

A box declares a service, `"external": {"alerts": {"push": {}}}`, and calls `send`:

```json
{"to": {"topic": "orders"}, "title": "Pickup ready", "body": "Order 7 is ready",
 "url": "/shop/orders/7", "tag": "order-7", "ttl": 3600, "urgency": "high", "collapse": "order-7"}
```

- **Who.** `to` is exactly one of `{user_id}`, `{topic}`, `{subscription}`, or
  `{everyone: true}`, and `app` optionally narrows it. Anything else is refused: a malformed
  `to` never widens into everyone.
- **What.** The payload is at most 3072 bytes of JSON. `url`, `icon`, and `badge` are paths on
  the site.
- **When.** It is an outbox element: delivered after the request commits, within the tenant's
  daily cap for the service, retried per the outbox. The box needs a database, as mail does.

**Delivery** encrypts the payload for each subscription and posts it, with the headers below.
`push_send` is an operator's way to try it.
- **Headers:**
  - `Authorization: vapid t=…, k=…`;
  - `Content-Encoding: aes128gcm`;
  - `TTL`;
  - and, when given, `Urgency` and `Topic` (the collapse key).
- **Gone subscriptions.** A 404 or 410 means the browser dropped it, and so does the host.
- **Retries.** The outbox retries an element while any send failed in a way that may pass:
  no answer, 429, or 5xx. Each subscription already reached under the element's
  idempotency key is skipped, so a retry repeats nobody's notification.
- **Logging.** Each post is written to the egress log, without the endpoint's path.

**The cryptography** is the `webpush` package.
- **Checks.** RFC 8291's Appendix A example encrypts byte for byte. A flipped bit fails to
  decrypt, and VAPID JWTs verify against the host's key.
- **OpenSSL.** Every curve and cipher operation is OpenSSL 3.5.1's libcrypto.
  `install-deps.sh` builds it statically and pinned, after checking its published SHA-256.
- **Deploys.** The server needs nothing new, since deploys build here and copy one binary.

## 6. Tools

| tool | does |
| --- | --- |
| `pwa_put` | checks and writes an app, and answers its URLs, its tags, and any install warnings |
| `pwa_get` | the definition, the manifest as served, and the tags |
| `pwa_list` | apps with scope, worker, push, and subscription counts |
| `pwa_delete` | removes an app; installed copies keep their cache until the worker updates |
| `pwa_subscriptions` | counts by app and topic, signed in or not, failing, never the endpoints themselves |
| `push_send` | a push now, to try it |

`pwa_get`, `pwa_list`, and `pwa_subscriptions` are read tools (028 § 7).

## 7. Checked

- **Unit tests:**
  - parsing and refusals;
  - longest scope;
  - the tags;
  - the marker in and out of scope, with the tenant's partial winning;
  - the built-in base page.
- **Host tests:**
  - a page in scope links its manifest, and one outside doesn't;
  - the manifest's fields and its 304;
  - the worker's headers;
  - `register.js` carries the key;
  - subscriptions are refused from another origin or for a non-push endpoint;
  - a box's push is delivered after commit to only the topic's subscriber, decrypted by
    the test as a browser would, with a verified VAPID JWT, and sent once;
  - a 410 drops a subscription;
  - a numeric `user_id` reaches nobody it shouldn't;
  - signed-out and push-off apps are refused.
- **A real browser** (headless Chromium, against the demo host):
  - the worker registers for `/shop/` and controls the page after a reload;
  - `Page.getAppManifest` reports no errors, and `Page.getInstallabilityErrors` none;
  - offline, `/shop/` loads from the cache, and an unvisited page in scope shows the
    fallback.

## 8. Limits and what is left out

- **iPhone push** works only once the app is on the home screen (iOS 16.4 and later). Push
  can't be tried end to end here: a headless browser has no push service.
- **Offline signed-in pages** aren't kept, by design. An app that needs them brings its own
  worker.
- **Background sync, periodic sync, file and protocol handlers, and `share_target`** pass
  through the manifest. A tenant's own worker or a box route handles them; the host's worker
  doesn't.
- **A box can't look up an anonymous subscription by person.** It reaches anonymous
  subscribers by topic, `everyone`, or the subscription id the page received and posted to it.
- **Not built:** a panel view of apps and subscriptions, per-person push limits beyond the
  outbox's daily cap, and scheduled pushes (a timer route can send).

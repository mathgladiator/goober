# The Terminal

> Status: machine-authored and **not ratified**. Recorded on 2026-10-26. It is how goober
> keeps the contract of `999.Mobile.md` today: two example boxes, `terminal` and `desk`,
> over one tenant database, on top of the OAuth of `009.OAuth.md`. The code is in
> `host-src/examples/boxes/terminal/`, `desk/`, and `shared/`, and
> `host-src/tools/terminal_e2e.py` checks it end to end. Where it departs from 999 or
> another human doc, §7 says so, and the human doc wins until it is updated.

## 1. The shape

| piece | who calls it | what it may do |
| --- | --- | --- |
| `terminal` box, `/terminal/v1/` | The person: a browser, or the dumb app as the person client `dumb-terminal` | Read everything; insert decisions; register devices; record events. |
| `desk` box, `/desk/v1/` | The person's agents (every route says `"agents": true`), and the person | Insert approvals and read them; set alarms, dashboards, and settings; read devices without push tokens. |
| Database `terminal` | Both boxes, schema `terminal1` | One file per tenant: `storage/sqlite3/$tenant/databases/terminal.db`. |

Every route of both boxes requires `owner`, the executive's seat in a personal realm
(999 § The routes). No terminal route says `"agents": true`, so an agent holding exactly
the owner's roles still gets 403 from every terminal route (009 §5).

## 2. No agent can decide an approval

999 asks that the agents' box "can insert a request but have no write path to its status".
v1's direct SQL grants inserts per table (008 §9), so a status column in the approvals
table would be guarded only by the desk box's code. Instead, **a decision is its own
table**:

| table | terminal box | desk box |
| --- | --- | --- |
| approvals | read | read, insert |
| decisions | read, insert | read |

An approval is pending while it has no decision row and hasn't expired. The desk box has
no grant that writes to `decisions`, so the answer to "can an agent approve its own
request?" is in the manifest's grants, where the checker and the approver can read it,
not in code.

## 3. The routes

**terminal** (999 § The routes):

| route | does |
| --- | --- |
| GET /terminal/v1/me | `{id, name, email}` from the request's user; `name` is the email's local part, since identity holds no names. |
| GET /terminal/v1/config | `{name}`: the settings name, else the domain. No `push` (decision 7 is open), so the app pulls hourly. |
| GET /terminal/v1/sync | The snapshot, built by SQLite in one statement: `server_time`, at most 64 alarms (newest first), pending approvals newest first (at most 200), the dashboard menu (at most 50), and `default_location` when one is set. Absent optional fields are left out, never null. |
| GET /terminal/v1/dashboards/{dashboard_id} | The stored dashboard, with `generated_at` stamped if it has none. Settings arrive as query parameters and are ignored by stored dashboards. |
| POST /terminal/v1/approvals/{approval_id}/decision | §4. |
| POST /terminal/v1/devices | `{platform, app_version, device_name, timezone, push_token?}`, one row per person and device name, replaced on repeat. 204. |
| POST /terminal/v1/events | `{type, at, idempotency_key, alarm_id?, minutes?}`; `minutes` only for `alarm_snoozed`, 1 to 120; a repeated key is a 204 that stores nothing. |

**desk:**

| route | does |
| --- | --- |
| POST /desk/v1/approvals | `{task, description?, requester?, risk?, expires_at?, actions?}`; 201 `{id, status}`. `requester` defaults to the agent's client_id; `requested_by` always records it. |
| GET /desk/v1/approvals, /desk/v1/approvals/{approval_id} | Status: pending, approved, denied, approved_with_feedback, or expired, with feedback and `decided_at`. Agents poll this until the outbox and internal routes exist (§6). |
| GET /desk/v1/alarms, PUT and DELETE /desk/v1/alarms/{alarm_id} | An Alarm (999 § Alarms), checked field by field, stored with its id. At most 64. |
| PUT and DELETE /desk/v1/dashboards/{dashboard_id} | A Dashboard: a title, at most 20 settings and 20 pages of at most 50 widgets, each with a type. |
| PUT /desk/v1/settings | `{name, default_location?}`. |
| GET /desk/v1/devices | Device names, platforms, and time zones, for an agent planning "6am in their zone". The strategy can't read push tokens or row ids. |
| timer `desk_morning` | At 6am in each device's zone, a notification when approvals are waiting, or none (`014.Time.md` §4). |

## 4. Decisions

The body is `{decision, feedback?, decided_at, idempotency_key}`, with the same key in the
`Idempotency-Key` header (999 § Approvals). `approve` carries no feedback;
`approve_with_feedback` needs some (at most 4000 characters); `deny` may have it. A
decision must be one of the approval's `actions` when it lists them.

| situation | answer |
| --- | --- |
| No such approval | 404 |
| Already decided with the same key | 204, nothing changes |
| Already decided with a different key | 409 |
| Expired | 409 |
| Otherwise | 204; one row inserted into `decisions`, unique per approval, so a race can't land two |

The decision commits with the request, through the request transaction of 008 §6. Telling
the agent is not yet an outbox element (§6).

## 5. Checks the boxes make until the host does

The desk declares its bodies and tool inputs in `desk.openapi.json`, which the host checks
(`011.Types.md`). The terminal's routes don't declare types yet, so both boxes still check
the strict subset themselves, in `shared/goober.rs`:

- objects are closed: an unknown field is a 400, and so is a null where a value is expected;
- strings have maximum lengths, enums are checked, integers have ranges;
- instants must be RFC 3339 UTC, wall times `HH:mm`, dates `YYYY-MM-DD`;
- arrays are bounded.

The desk also refuses descriptions and texts the terminal would quarantine, as 999 § The
markdown dialect allows a box to: control characters, bidi controls, zero-width and other
invisible characters, Unicode tags, more than 64,000 characters or 2,000 lines, and links
to `javascript:`, `data:`, `file:`, `intent:`, or `vbscript:`. Alarm titles and bodies get
the same check for hidden characters. The terminal still checks everything itself.

## 8. Trying it

```sh
just run              # the demo host, with dumb-terminal registered as a person client
just examples         # deploys the terminal and desk boxes and stores terminal1
just terminal-e2e     # plays the app and an agent against it: 55 checks
```

In the dumb app, add the server `localhost:8080` (desktop), `10.0.2.2:8080` (the Android
emulator, which local mode now routes to the platform domain like `localhost`), or run
`adb reverse tcp:8080 tcp:8080` and add `localhost:8080` on a phone. Sign in as the
tenant's owner; the code is printed in the terminal running the host.

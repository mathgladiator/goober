# Types and Declared Requests

> Status: machine-authored and **not ratified**. Recorded on 2026-10-26. It builds the
> part of `036.Json.md` and `037.Http.md` that the host can enforce without generated
> code: a box's types document, and requests checked against what each route declares
> before the box wakes up. The code is the `types` package plus `manifest`, `boxes`, and
> `host`. Where it departs from a human doc, §6 says so, and the human doc wins until it
> is updated.

## 1. The types document

The manifest names it, as 036 shows: `"types": "orders.openapi.json"`, a plain file name.
The document travels with the version: `version_upload` takes it as `types`, and
`tools/goober.py deploy` reads the file beside the manifest. The host stores it as
`boxes/$box/versions/$version/types.json`, and it joins the version's hash. A manifest that
names a `json:$Type` without a document, or a type the document doesn't have, is refused
at upload.

Only `components.schemas` is read, and every schema must be in the strict subset of 036:

| accepted | notes |
| --- | --- |
| `integer` with `format` `int32` or `int64` | `minimum`, `maximum`, `default` |
| `number` with `format` `float` or `double` | `minimum`, `maximum`, `default` |
| `boolean` | `default` |
| `string` | `maxLength`, `minLength`, `enum`, `default`, and `format` `date-time` (RFC 3339 in UTC, ending in `Z`) or `date` |
| `object` | `properties`, `required`, and `"additionalProperties": false`, which is mandatory |
| `array` | `items` and `maxItems`, which is mandatory; `minItems` |
| `$ref` | `#/components/schemas/$Name` only, standing alone |
| annotations | `description`, `title`, `example`, `examples`, `deprecated`, `readOnly`, `writeOnly` |

Refused by name: `oneOf`, `anyOf`, `allOf`, `not`, `patternProperties`, `nullable`, type
lists (so no null), `const`, `pattern`, `multipleOf`, exclusive bounds, `uniqueItems`,
`prefixItems`, and the rest of JSON Schema. Recursive types are refused. `format: token`
is refused until the host signs tokens. Any other keyword on a schema is refused rather
than ignored. Type names are a letter followed by letters, digits, or `_`.

## 2. Checking a value

A check walks the schema and the value together and stops at the first problem, naming
its path: `$.lines[2].sku: is required`. It refuses unknown fields, nulls ("leave the field
out instead"), wrong types, numbers out of range or with fractions where an integer is
wanted, strings over `maxLength` counted in characters, and arrays over `maxItems`.

What the box receives is the checked value, not the original text: missing fields with a
`default` are filled in, and every int64 becomes a string of digits, the form 021 wants
on the wire. An int64 arrives as either a JSON number or a string of digits.

## 3. What a route declares

| field | the host |
| --- | --- |
| `body: "json:$Type"` | Needs `Content-Type: application/json` (else 415), parses it (else 400), checks it (else 400 with the path), and hands the box the checked JSON. |
| `body: "text"` or `"binary"` | Accepts the body as it is. A `get` or `delete` can't declare a body. |
| `max-body-bytes` | Refuses a larger body with 413. The host's `limits.body-max-bytes` still applies first. |
| `query` | An object of inline single-value schemas. The box sees only these parameters, typed (`"limit": 5`, not `"5"`), with defaults filled in; a bad value is 400. Without a `query` block, every parameter reaches the box as a string, as before. |
| `request-headers` | A list of lowercase header names. The box sees only these. `authorization`, `cookie`, and `goober-*` can't be named. Without the list, every header but the credentials reaches the box, as before. |
| `response: "json:$Type"` | A 2xx JSON answer must pass the type. If it doesn't, the request's database writes are rolled back, the caller gets a 500, and the box's log says why, so a box can't leak a field its type doesn't name. On success the caller gets the checked JSON. |

Refusals are JSON: `{"error", "status", "request_id"}`, with the message naming the type
and path, like `Ask $.risk: must be one of unknown, low, medium, high`.

`response` also accepts `json`, `text`, `html`, `markdown`, and `empty`. Only `json:$Type`
changes anything yet.

## 4. For agents

`Types::json_schema` turns a named type into a self-contained JSON Schema with the
`$ref`s inlined, which is what MCP's `tools/list` gives agents as `inputSchema`
(`012.Agents.md`). An int64 is described as a string with a digits pattern, since that is
what crosses the wire.

## 5. Tests

`types/test/types_test.cpp` covers every refusal, every check, query text, and the JSON
Schema. `manifest/test` covers the new route fields and `check_types`.
`host/test/agents_test.cpp` drives typed bodies, queries, headers, sizes, typed responses
with a leaked field, and uploads with a missing or bad document.

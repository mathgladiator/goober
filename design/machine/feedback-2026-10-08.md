## 2. The design in one breath

Goober is a bet that agents will write most software, and that the answer to not trusting them is "better boxes, with finer scope" [000 §Introduction]. It must run as **one binary on a laptop from day one** [005 §Developer Velocity and the Sandbox].

**Manifests and boxes.**
- A box is an ephemeral WASM reactor with no POSIX inheritance [000 §The Foundational Thinking; 010 §Start with Hello World].
- Its manifest is "the executive summary of what a box can do" [150 §Deeper on Manifests]. A **config** is a manifest with no box [012 §A config is a manifest with no box].
- Every field is defined once [150, throughout]. Platform keys are hyphenated, and names people choose may be styled however they like [010 §Start with Hello World; 150 §Rules every field obeys].

**Trust comes from the host, marked with "!".**
- Values the host vouches for are **reserved identifiers**, written `{!tenant}`, `{!user_id}`, `{!to}`, and so on. Each has exactly one way to be set [018 §The reserved identifiers; §How each one can be set].
- A `{name}` without "!" is caller-chosen and treated that way [018 §The convention].

**Identity and domains.**
- Identity is **per domain**: each primary domain is its own realm [013 §Identity is per domain]. The one exception is **global host identities** with `host:$role` [013 §The exception: host identities].
- Domains are a registry of primaries and redirects, with soft verification (always on, through Caddy's ask) and optional hard verification (TXT) [015 §The domain registry; §Soft and hard verification].

**Routes, conflicts, and traffic.**
- Every route says who may reach it [150 §Reachability].
- **There is no priority in a manifest.** A conflict is shipped by up-revving through approval, and the operator picks a traffic decision: hold, A/B test, slow roll out, or cut over [019 §The default: reject; §Shipping a conflict].

**Data.**
- Strategies use well-known patterns, `by_id` and `by_index`, with `query` iterators and direct SQL above them [020 §Data Flow; 028 §Three levels of reach].
- Every write has a **name and a kind**: insert, update, upsert, patch, or patch-except [020 §Every write has a name and a kind].
- A request's writes commit as a **bundle**, where every part happens at least once [025 §Write sets and bundles]. Effects ride the outbox [035].
- A schema is a **partial set of tables**. Allowed changes apply immediately, and the rest are refused [420 §A schema is a partial set of tables; §The kinds of change].

**Time, files, and keys.**
- Timers are host routes, or **by_timer** sources where each active row is a fire carrying the whole row [045 §Data-driven timers; §What a fire is].
- Uploads go through a **ledger** with mark and sweep, and an `asset` response streams a file without waking a box [060 §The upload ledger; §Serving a file to a browser].
- Keys are envelope-encrypted, with only the root key in the vault [064 §Envelope encryption]. **A missing key is a 500, and it becomes an urgent key request** [325 §Missing keys are the platform's failure].

**Shipping and operating.**
- Versions are hash-named [310 §The artifact], approved by people or by policies [305 §Policies], and ramped by the traffic controller [310 §The traffic controller].
- Operations run on a reserved surface that never sees user data [300 §Access logs]. Quotas are set by operators [390 §Who sets quotas]. **Everything has an API, except approval** [410 §The Operator API].
- Services own leased, fenced resources in one registry [400 §One registry for everything that is owned; §Leases, with fencing].

**Stability.** Boxes code against **capabilities** with swappable providers, redirect dead vendors to **adapter boxes**, pin every piece of host code, and are **replayed** before every host release [330, throughout].

## 4. What is unique

The good news first, and today it comes in crates.

### 4.1 Writes you can read

Every way a box can change a table is now a named line in the manifest, like `set_status: patch [status]` [020 §Every write has a name and a kind]. That's the "remove the words" philosophy applied to *mutation*:
- Reviewers see exactly which columns a box can touch.
- Migrations know exactly which writes a dropped column affects [420 §Writes across versions].
- `by_index` updates are checked against the group before they apply [020 §Writes by pattern].

I don't know of another platform where write *intent* is declared per column, ahead of time, and enforced at the boundary.

### 4.2 The "!" convention

One character marks whether a value can be trusted [018 §The convention]. It's tiny, it's legible, and it turns a whole class of confused-deputy bugs into a lint rule. Readers of a manifest learn it in five seconds.

### 4.3 Missing keys page the right person

Most platforms treat a missing credential as the application's problem. Here, it's the **platform's 500**, recorded, ranked, and sent to whoever can fix it:
- system keys go to operators,
- tenant keys go to the tenant owner, through the *system* mailer, in case the missing key is the tenant's own mailer,
- user keys go to the person at their next sign-in [325 §Urgent key requests].

The request closes itself when a call with the new key succeeds. That is operations designed by someone who has been paged at 3am.

### 4.4 Timers that disable themselves

A one-shot timer flips its own `active-field` to false in the same bundle as the fire's writes [045 §Example: a reminder the day before an appointment]. Combined with idempotent internal routes [039 §Idempotent internal routes], timers get at-least-once delivery across a cluster with once-only work. The reminder that fires twice because someone forgot to switch it off is simply gone as a bug class.

### 4.5 Migrations by refusal

Instead of building a powerful migration engine, [420] builds a *small* one: the host only performs changes it can emulate perfectly for every older box, and the API refuses the rest [420 §What is refused]. That's the schema-registry idea from Protobuf and Avro applied to SQLite tables, with per-tenant files making in-place changes cheap. It is genuinely unusual, and its simplicity is the point.

### 4.6 Still shining

Contracts that outlive vendors [330], approval by kind of change [305 §Policies], operations without user data [300 §Access logs], and the pattern language with no regex [012 §The pattern language] all remain distinctive.

## 6. Limits

The medicine, served with a smile and a spoonful of sugar.

### 6.1 The limits

1. **The `.schema` format doesn't exist yet,** and it is now load-bearing everywhere:
   - [420] needs declared defaults, nullability, and indexes;
   - [060 §Taking ownership] needs the `goober: object` annotation;
   - [028] prepares queries against it;
   - [045] reads typed rows from it;
   - [020] stamps structures from it.

   Everything depends on a file nobody has specified.
2. **Tenant-scoped roles still appear in eight docs.** `owner/{!tenant}`, `admin/{!tenant}`, `member/{!tenant}`, and `editor/{!tenant}` are used in [039, 050, 060, 070, 300, 310, 315, 320]. But roles are now realm-wide, with "/" scoping *within* a tenant [013 §Grant roles]. Under today's rules, `owner/{!tenant}` means "the owner of a scope named bobs_plumbing," which no one holds, so **every one of those routes is unreachable as written.**
3. **The tenant-from-path rule contradicts itself.**
   - [020 §Patterns, tenants, and limits] refuses a database built from a path argument "on any route except an internal one."
   - [020 §Where scope comes from] and [013 §The exception: host identities] allow it on http routes whose requirements all name host roles, and 013's support console does exactly that.

   One of them has to give.
4. **Cluster placement is described two ways.**
   - Routing says the first host to need an unowned database acquires its lease [400 §Routing].
   - Timers say the registry places databases and timer partitions "with the same consistent hash" [400 §Timers in a cluster].

   Lease-on-demand and consistent-hash placement are different systems.
5. **Timer tenancy has two mechanisms.** [018 §How each one can be set] says a timer sets `!tenant` *only* through `tenant-field`. [045 §Where timer state lives] and [400 §Timers in a cluster] also partition any `{!tenant}`-scoped source across every tenant in the registry, which sets `!tenant` implicitly. Both are reasonable, but 018 forbids the second.
6. **The cost model is still missing** (limit 1 from 10-06). [390] adds quotas without units for CPU or calls, and [305 §Deployment modes] still compares health against thresholds that don't exist.
7. **Schema changes have no approval kind.** [420 §Warnings before anything happens] says every schema change is approved by a human, but [305 §What an approval reads] has no `schema` kind, and no rule says a contraction can never be waved through by policy.
8. **The two shadows** (from 10-06) remain: `deployment.mode: "shadow"` has no network, while [310 §Shadowing] allows `shadow-calls`.
9. **`fetch`, federation, consent, and discovery** are all still missing, and they matter to the use cases (§10).
10. **The trusted computing base grew again:** asset streaming, schema projection, MIME parsing, the idempotency store, and timer planning all live in the host.
11. **Idempotency keys are kept "for long enough"** [039 §Idempotent internal routes]. That's not a number, and the store's size and retention decide both correctness and disk use.

### 6.4 A careful look at [420], since the author is unsure

The author asked themselves the right question, so here is my honest, cheerful read.

**What's strong:**
- Refusing what can't be emulated keeps the host small.
- Immediate expansion and indexing are obviously right for per-tenant SQLite.
- Named writes make old boxes safe against new columns [420 §Writes across versions].

**What I'd worry about:**
- **Immediate contraction is the sharpest edge in the whole design.** It drops a column's data on every tenant database at once, while older boxes may still write it, with those writes silently discarded [420 §The kinds of change]. That's correct *mechanically*, but it means a single approval can destroy data everywhere. The checker warns [420 §Warnings before anything happens], but a warning isn't a gate.
- **"Reads will be invented."** An older box reading a dropped column gets a default, so it may make decisions on values that aren't real. That's the opposite of failing loudly.
- **Defaults must exist for every column** for the projection to be well defined [120 §The boundary across migrations]. That only works once the `.schema` format requires them (limit 1).
- **The author's own goal 2** wants old boxes to run unchanged for years. Immediate contraction is the one move that *can* change an old box's behavior without its code changing.

**My suggestion** (§7.4) keeps the simplicity and adds exactly one gate: **a contraction may only apply when no deployed box still has a named write that touches it.** Thanks to named writes, that's a query the checker can answer exactly, not a guess. The event-source exploration in `design/machine/db.unify.event.source.md` is the longer-term answer for changes that 420 refuses.

## 7. Proposals

### 7.1 Sweep the roles (limits 2 and §6.3)

Replace `owner/{!tenant}`, `admin/{!tenant}`, `member/{!tenant}`, and `editor/{!tenant}` with `owner`, `admin`, `member`, and `editor` across the eight docs, and fix the `owner/$tenant` comment in 015. Add one sentence to [013 §Grant roles] saying role names like `editor` are product-defined strings. That's mechanical, it should take minutes, and it makes every example reachable again.

### 7.2 Write the `.schema` reference (limit 1)

Write a twin of [150] for `.schema` files, covering:
- tables as a partial set [420 §A schema is a partial set of tables],
- column types mapped to the [036] vocabulary,
- **required defaults** for every column,
- nullability, indexes, primary keys, `goober: object` references [060 §Taking ownership], and timer columns [045].

This is the single document that would most raise one-shot readiness (§12).

### 7.3 One placement rule for the cluster (limit 4)

Make consistent hashing the *default owner* for databases, timer partitions, and services alike, with leases and epochs as the *mechanism* [400 §Leases, with fencing]. On first need, a host asks the fleet service, which grants the lease to the hashed owner rather than to the asker. That one sentence reconciles [400 §Routing] with [400 §Timers in a cluster].

### 7.4 One gate on contraction (limit 7, §6.4)

- Add a `schema` kind to [305 §What an approval reads], and make **contractions never-waivable**, alongside reach, power, and safety.
- Then add one rule to [420]: a contraction applies only when no deployed manifest pins a schema version with a named write touching the dropped column or table. Until then, it's held, and the checker names the writes holding it.
- Finally, require a backup checkpoint per database before the drop, so "data will be dropped" is recoverable for the retention window [025 §Second, data that embeds in a machine, packs up, and goes away].

### 7.5 Settle the tenant-from-path rule (limit 3)

Pick one, and fix both docs to match:
- **(a)** Keep the host-role exception, and add it to [020 §Patterns, tenants, and limits] and [150 §Data]'s `database` row.
- **(b)** Move the support console to an internal service called by a host-role http route that passes `{tenant_slug}`.

I'd pick **(a)**, since host roles are already trusted and the checker proves the box is read-only [013 §The exception: host identities].

### 7.6 Timer tenancy, said once (limit 5)

Amend [018 §How each one can be set] to allow both mechanisms: implicit partitioning when a source's database is scoped by `{!tenant}`, and `tenant-field` for unscoped sources. Both look the tenant up in the registry.

### 7.7 Numbers for idempotency (limit 11)

Name the retention, like 7 days by default, matching the sweeper's window [060 §Mark and sweep]. Make it bounded per tenant by the quotas design [390 §What comes later]. Add `idempotency_keys` to the tenant directory's documented contents.

### 7.8 Carried forward

- The cost model (§7.2 of 10-06).
- Federation with a parent realm (§7.3 of 10-06).
- `fetch` (§7.8 of 10-06).
- Renaming one shadow (§7.5 of 10-06).
- Agents proposing with evidence (§7.9 of 10-06), which [410] now makes easy to wire.

## 8. Security evaluation

### 8.1 What changed in the threat picture today

- **Reserved identifiers** close a whole class of confused-deputy bugs [018 §The invariants].
- **Missing keys fail closed** and are visible [325 §Missing keys are the platform's failure]. Agents can never enter a key [325 §For agentic operators; 410 §Roles].
- **Host identities are global and can dive into tenants** [013 §Diving into a tenant]. That's the most powerful new capability today. It's audited, but **tenants still can't see that audit**, which the identity doc itself defers [013 §The exception: host identities].
- **Asset routes serve only attached files** [060 §Serving a file to a browser]. That's good, but anyone who passes the route's requirements can fetch any attached file under the folder pattern. Scoping is only as tight as the path template.
- **Internal routes may bind tenants from path arguments** [020 §Patterns, tenants, and limits; 039 §Binding to a tenant]. A caller passing the wrong tenant is a cross-tenant read or write. The checker *flags* it but can't prove it.
- **Immediate contractions** are a new data-loss vector through approval (§6.4).
- **The operator API** puts every power behind one surface [410]. That's a fine design, and also a juicy target, so its port and network placement matter [300 §The reserved surface].

### 8.2 By adversary

| adversary | strengths today | gaps | rating |
| --- | --- | --- | --- |
| Malicious box | Named writes, group checks [020 §Writes by pattern], "!" values, untrusted pointers [120 §Getting data out] | `interior_ok` still waves code through [305 §Policies]; asset path templates | **Strong** |
| Malicious tenant user | Realms, deny by default [013], quotas [390] | Catch-all spam [038 §Catch-all routes and inboxes]; quota refusals at commit after the work is done | **Good** |
| External attacker | Soft and hard verification [015 §Soft and hard verification]; `/internal/` only on the private interface [041 §Reserved internal routes] | Internal hop authentication is described for Stalwart [038 §From Stalwart to a route] but not uniformly for Caddy's ask or NATS | **Good** |
| Operator or infrastructure | Access logs without user data [300 §Access logs]; key values are write-only [325 §What the panel shows] | Host identities can dive into any tenant [013 §Diving into a tenant], and tenants can't see it | **Adequate** |
| Supply chain | Pins, replay [330] | Unsigned artifacts; the parser list in the host keeps growing | **Needs work** |
| Agent acting for a user | MCP-only tokens [050 §Who is calling]; can't touch keys or approve [410 §Roles] | Agents of host owners hold host-owner reach on the operator API, minus keys and approvals | **Good** |

### 8.3 Under real traffic

- **A key expires at a vendor.** Every request that needs it returns a 500 [325 §Missing keys are the platform's failure]. That's correct, and the urgent queue makes it fast to fix. **Contain** the 500 storm by short-circuiting calls after N consecutive rejections.
- **A schema change lands on 10,000 tenants.** Each database catches up "before it serves its next request" [420 §The kinds of change], so the first request per tenant pays the ALTER. **Contain** it with background application, rate-limited, before opening the gate.
- **Quota refusals at commit.** Byte quotas refuse at commit [390 §Where quotas are enforced], so the box did all the work for nothing, and a retry loop does it again. **Contain** it with a pre-check and a cool-down.
- **Midnight timers.** Consistent hashing and spreading help [400 §Timers in a cluster; 045 §The rules of time]. ✅
- **Upload resume across hosts** pulls partial files between machines [060 §The upload ledger], which is a bandwidth spike during a host drain. **Contain** it by forwarding rather than pulling, by default.
- **Catch-all inboxes attract spam** [038 §Catch-all routes and inboxes]. RCPT-time rejection helps, but a catch-all accepts every local part. **Contain** it with per-tenant mail quotas [390 §What comes later].

### 8.4 Top ten

1. Settle the tenant-from-path rule, and require callers of tenant-binding internal routes to pass a value derived from `{!tenant}` (§7.5).
2. A tenant-visible audit of host-identity actions in their realm [013 §Diving into a tenant].
3. Gate contractions (§7.4).
4. Authenticate every internal hop: Caddy's ask, NATS, and internal RPC, not just Stalwart [041 §Reserved internal routes].
5. Sandbox the parsers (markdown, templates, images, MIME) in WASM.
6. Sign artifacts.
7. `fetch` with private-address blocking.
8. Per-box and per-agent-session quotas for public toys [390; 050 §Agentic considerations].
9. Scrub replay corpora [330 §Proving the host didn't change anything].
10. Bound the idempotency store (§7.7).

## 9. Operating the system

### 9.1 Humans

- **The operator** gets a much richer day:
  - urgent key requests [325 §Urgent key requests],
  - quota red lines [390 §Red lines],
  - schema status per database [410 §Data, schemas, and migrations],
  - traffic plans for conflicts [019 §Shipping a conflict],
  - drains and leases [400 §Moving things on purpose].

  *Their pager:* urgent keys, dead letters, rollbacks, quota walls, and clock skew.
- **A tenant owner** gets warnings at 95% of quota by email [390 §Red lines] and requests to enter missing keys [325 §Urgent key requests]. They still can't see what host operators did in their realm.
- **An end user** is asked for their own keys with a clear label [064 §Per-user keys], and never sees a key again.

### 9.2 Agents

- **An agent building boxes** writes named writes it can reason about [020 §Every write has a name and a kind]. It gets refusals with explanations for schema changes it can't make [420 §What is refused], and ships through the same API as humans [410].
- **An agentic operator** can now do nearly everything an operator can [410 §Roles]. It can't approve and can't touch keys, and it will find that frustrating exactly where it should.

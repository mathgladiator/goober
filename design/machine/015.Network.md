## 1. Declaring a service

```json
{
	"external": {
		"mailer": {
			"base": "https://mail.example.com/v3",
			"credentials": "keys/system/mailer",
			"auth": { "header": "Authorization", "prefix": "Bearer " },
			"methods": {
				"sendMessage": {
					"verb": "post",
					"path": "/messages",
					"require": { "body.to": "{!email}" },
					"idempotency": "header/Idempotency-Key",
					"delivery": { "attempts": 8, "backoff-ms": 1000, "within-ms": 600000 },
					"budget": { "calls": 3 }
				},
				"status": { "verb": "get", "path": "/messages/{message_id}" }
			}
		}
	}
}
```

| field | meaning |
| --- | --- |
| `base` | `https://host[:port][/prefix]`, no query. Or `http://127.0.0.1:PORT` / `http://localhost:PORT`, which the host calls only in local mode, for development and tests. |
| `credentials` | A key name, `keys/system/$name` or `keys/tenant/{!tenant}/$name`. Never a value. |
| `auth` | Where the key goes: `header` (default `authorization`) and `prefix` (default `Bearer `). |
| `methods.$name.verb` | get, post, put, patch, or delete. |
| `methods.$name.path` | Appended to the base; `{name}` parameters come from the call's `path` object. |
| `effect` | `none` (sent now; the default for get), `outbox` (after commit; the default otherwise), or `immediate` (effectful, sent now). |
| `idempotency` | `header/$Name`: where the host puts each outbox element's key. |
| `delivery` | Attempts (1 to 50), first backoff (100 ms to 1 h, doubling), and a deadline (up to 7 days). |
| `budget.calls` | Calls per request, 1 to 100 (default 10). The next one fails without leaving the host. |
| `require` | `body.a.b`, `query.x`, `path.x`, or `header.x`, set to a literal or `{!email}`, `{!user_id}`, `{!tenant}`, `{!domain}`. The host's value overrides whatever the box sent. A user value with nobody signed in fails the call. |

`openapi` and `operation` are accepted with a warning and not read (§7). `box`, `capability`,
and `provider` are refused for now.

## 2. Calling

`goober_call(service, method, request) -> i32`, then `goober_result_read`. The request is
`{"path": {...}, "query": {...}, "body": ...}`; any other key is refused.

- The URL is the base, the path with each parameter percent-encoded (so a value can't add a
  segment, a query, or a fragment), and the query sorted and encoded.
- A string body is sent as `text/plain`; anything else as JSON.
- **effect none or immediate:** sent now through curl, with no redirects followed, https
  only (except the loopback rule), at most 10 seconds and never past the request's own
  deadline, and replies capped at 4 MiB. Path values `.`, `..`, and empty are refused. The answer
  is `{"status", "content_type", "body"}`, plus `"json"` when the reply is JSON. A missing key
  answers `{"error"}` and nothing goes out.
- **effect outbox:** captured, answering `{"accepted": true, "key"}` (035 § What the box
  sees). The key is derived from the request id and the element's place in the request, so it
  is the same on every attempt.

Headers and the credential travel to curl in a private 0600 file, never on its command line.
Every call, now or from the outbox, is a line in `logs/egress.log`: tenant, box, service,
method, verb, URL without its query, status, time, and byte counts. Bodies and query strings,
which can hold secrets and personal data, aren't logged.

## 3. The outbox

An element is enqueued if and only if its request commits (035 § The invariants):

- A box with data keeps its outbox in the database of its first strategy, in a host-owned
  `goober_outbox` table, inserted in the request's own transaction. A request that answers 5xx
  or traps rolls the elements back with its writes.
- A box without data has no transaction to join; its elements go to
  `storage/sqlite3/$tenant/outbox.db` once it has answered below 500.

A dispatcher thread wakes every two seconds and walks every outbox an active box could have
filled (and, once a minute, every outbox in storage, so a removed box's elements aren't
stranded). Each service is delivered from its own oldest pending element, so one stuck service
never holds up another. For each element:

| outcome | then |
| --- | --- |
| 2xx | done (deleted after 7 days) |
| 4xx other than 408 and 429 | dead: asking again won't help |
| anything else, or a missing key | tried again after the backoff (doubling, at most an hour), until the attempts or the deadline run out, then dead |

Order holds per service: once an element of a service is waiting, the ones behind it wait too,
so "create the ticket" never lands after "close the ticket". A dead element is reported on the
host's console and listed by `outbox_dead_letters`; `outbox_retry` gives it ten more minutes
from the first attempt, and `outbox_discard` deletes it.

**Results (035 § What the box sees).** A method may name `"result-route": "on_reply"`, one of
the box's `routes.result` routes (`{"on_reply": {"timeout-ms": 5000}}`, no requirements:
only the host calls it). When the element reaches `done` or `dead`, the dispatcher calls
`goober_route_on_reply` as a request of its own (method `result`, path `result:on_reply`,
user null, the tenant's first domain) with the body
`{"key", "service", "method", "outcome", "status", "body", "error", "attempts"}`. `key` is what
`goober_call` answered, so the box matches the outcome to its row. Its writes commit like any
request's, and it may queue more elements: a model's reply, then the mail that sends it. The
call is made once; if the box fails, the outcome stays in the outbox list. Upload refuses a
`result-route` that names no result route or sits on a method without `effect` outbox.
`delivery.timeout-ms` (1000 to 120000, default 10000) bounds one delivery, so a model API
fits. A slow delivery holds the dispatcher, which is one thread: other tenants' elements wait
behind it, at most two minutes. The fields live in `goober_outbox_more`, a table beside the
outbox, so outboxes made before them need no migration. Added 2026-10-28 for the email worker.

**A daily cap.** Besides each method's per-request budget, a tenant's boxes may queue at most
`limits.outbox-daily-per-service` outbox calls to one service in 24 hours (default 1000),
counted in `storage/outbox/daily.db` when the call is made. Past it, the call answers
`{"error": "over the host's daily limit: ..."}` and nothing is queued. Mail has its own limits
(018). Added 2026-10-28, so a looping email worker can't spend a model budget.

## 4. Keys

`storage/keys/system/$name` and `storage/keys/tenant/$tenant/$name`, each a 0600 file. Values
are 1 to 8192 printable bytes. Operators use `key_set`, `key_delete`, and `key_list`, which
shows names, when each was set, and a 12-hex fingerprint, never values (325 § write-only). The
host reads a value only to attach it to an outgoing request, at the moment it goes out, so a
rotated key takes effect on the next call or delivery.

## 5. Tests

`manifest/test` covers `external` parsing and refusals. `host/test/network_test.cpp` runs a
stand-in service and checks: a safe call with the key attached and a path value that can't add
a segment; a missing key failing in the box's hands with nothing sent; the egress log never
holding the key; an outbox call that waits for the commit; a failed request leaving neither its
note nor its call; a retry after a 503 with the same idempotency key; `require` overriding the
box's own field; delivery exactly once; a 400 dead-lettered and retried by an operator.

## 6. In boxes

## 7. Departures and what is missing

| doc | section | v1 says |
| --- | --- | --- |
| 030 | Bringing in a service | Methods declare `verb` and `path` in the manifest; no OpenAPI document is read, and no typed client is generated. |
| 030 | Consequences for the box | Safe calls are synchronous; an outbox call's outcome comes back on a result route (§ 3). The host doesn't yet own per-service rate limits. |
| 030 | Boxes talking to boxes | Not built (`box` is refused); waits for internal routes (039). |
| 035 | What the box sees | Result routes are built (§ 3), called once per final outcome; a result route that fails isn't called again. |
| 035 | Delivery | The outbox lives in the box's first database, or in `outbox.db` for a box without data (not atomic with anything, since there is nothing to be atomic with). |
| 064 | The vault | Keys are plain 0600 files: no root key, no envelope encryption, no rotation. |
| 325 | Missing keys are 500s | A missing key fails the call in the box's hands; the box decides. |
| 030 | Egress audit | Sizes and URLs are logged, not what went out and what came back. |

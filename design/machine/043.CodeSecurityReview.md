## For the human

These are decisions, not low-hanging fixes; nothing changed for them.

1. **Which connections may speak for the client.** With `behind-proxy` on, the host believes
   `X-Forwarded-For` from any connection, not only from the proxy. Setup (`tools/setup.sh`)
   offers 127.0.0.1 behind Caddy as the default, so normally only Caddy can reach it, but it asks
   and takes any address; a host listening publicly with
   `behind-proxy` would let anyone choose their rate-limit key and their `client_ip`.
   Options: (a) leave it, documented, since deploys bind locally (today's behavior); (b) a
   `listen.trusted-proxies` list of addresses whose header is believed; (c) refuse to start
   with `behind-proxy` on a non-loopback address. Recommendation: (c), a config check with no
   new field; (b) when a second proxy shape appears.
2. **Roles that gate the route that grants them.** R6 warns about `owner`. A route may also offer
   a role its own site's pages or tools treat as authority (`admin`, `editor`). The host can't
   know which roles mean power to a site. Options: warn on every option that appears in any
   `requirements` clause of the same manifest, or leave it to the review's widening list.
   Recommendation: the warning; it costs nothing and names the risk at upload.
3. **Agents and role grants.** Refused today (an agent's call isn't a person's act), as decided.
   Phase 39 lists MCP tools that grant as accepted but unbuilt; that stays the human's call.

Tracking it exactly means asking SQLite what each `ROLLBACK TO` undid. |
| N2 | `db_export` builds the whole result (up to 100,000 rows) as JSON and then as CSV in memory before sealing. | Bounded by the row cap and SQLite's 4 MiB value limit; streaming rows into the seal is a performance change for the performance review. |
| N3 | An export's record (`storage/exports/ID.json`) keeps the SQL in the clear, and a statement may hold a literal such as an address in its `WHERE`. | Storage is the host user's alone (`umask 077`), the record is deleted with the export after 7 days, and the audit log hashes addresses in the same SQL. |

## Checked and found sound

- **Savepoints.** The authorizer sees each `SAVEPOINT`, `RELEASE`, and `ROLLBACK TO` with its
  name; names starting `goober_` (any case) are refused; a release or rollback must name one
  the call opened; `BEGIN`, `COMMIT`, `END`, and a bare `ROLLBACK` stay refused. The host's own
  `BEGIN` runs before the first statement (savepoint statements included, since SQLite calls
  them read-only), so a box's outermost `RELEASE` never commits, and the session's check that
  SQLite left its transaction still catches a spoiled one.
- **Role grants.** Options are tenant roles, never `host:`; substituted values can't carry `/`
  or `:`; the target is `{!user_id}` or a parameter the requirements bind; agents and host
  identities are refused; nothing lands in a try, a dry run, a 5xx, or a failed commit; both
  audits name the box.
- **`client-ip`.** Only on post, put, patch, and delete (a GET's answer can be cached for
  someone else); every call that gets it is an audit line with the address as a keyed hash; a
  try gets 192.0.2.1.
- **`route_try`.** Writes, tools, mail, timers, and internal calls run on copies with
  `dry_run` set (no internal calls, nothing published or delivered, no roles); GETs run
  read-only; observers and the panel may only try GETs and HEADs; one try per operator at a
  time; tries stay out of traffic and the cache.
- **Change sets.** Each member is checked against the operator's scope as the single tool
  would be, at add, preview, apply, and rollback; a focused operator sees only their own sets;
  drafts never wait, apply and rollback do; `changeset_preview` runs look-only for observers.
- **Upgrade boxes.** The manifest refuses anything but `routes.upgrade` in one (no data,
  services, flags, or other routes); calls are pure (no clock, a fixed seed); `upgrade_start`
  needs a person's approval of the schema and a passed dry run, and refuses while an older box
  uses a rewritten table.
- **Schema steps.** A forced step skips the person only when its tables are empty in that
  database and no older box writes them, checked again inside the apply's transaction; a walk
  of several versions snapshots before a later step's rewrite too.
- **`count(*)` under narrow grants.** SQLite asks with an empty column only when no column is
  read; a `WHERE` on a column still asks for that column.
- **Error pages.** Rendered for nobody whatever the request carried; `{{request_id}}` is the
  host's own (an incoming `goober-request-id` header is replaced); `error-message/` is no page.
- **`keep-fragment.js`.** It changes only `return` values and same-origin sign-in links, and
  only after `#`; `safe_return` still decides every redirect (a path from `/`, no `//`, no
  control bytes or backslash, a fragment of at most 256 URL fragment characters).
- **`db_export`.** Read-only like `db_query`; sealed in memory under the tenant's key from the
  vault key, bound to tenant and id; never in backups; a read call for approvals but not a read
  tool, so observers and the panel can't make one; tenant-scoped for focused operators.
- **DKIM.** rsa-sha256 (1024 bits and up) and ed25519 only; `From` must be signed; `l=` refused;
  exactly one `From` with one address; alignment by the signing domain or a parent with a dot.
- **Caching.** Entries are keyed by the whole request document (the user and roles included
  for non-public routes) and go stale on database versions and on the flags the box read.
- **Logs.** Addresses in log lines, `client_h` included, are HMACs under the host's own key.
- **Tokens.** Names are `[a-z0-9_-]`, 1 to 63 characters; `operator_scope` names the identity
  every log records.

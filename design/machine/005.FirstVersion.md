# The First Version

> Status: machine-authored and **not ratified**. This records the decisions taken on
> 2026-10-22 from the human's answers in `design/QUESTIONS.md` (commit 2362f4d), plus
> the choices the human delegated ("pick the best", "you decide", "go with best
> practices"). Where a decision supersedes a human doc, the doc and section are named,
> and the human doc wins until it is updated. The code in `host-src/` follows this
> document. Identity, setup, local mode, and operator tokens were added after it, in
> `006.LocalIdentity.md`; sites, templates, and attachments in `007.Content.md`; and tenant
> databases in `008.Databases.md`.

The goal of v1 is a host the human can play with: a single machine that serves static content, runs WASM boxes behind HTTP routes, and is driven by an agent over MCP. Databases come next. Everything here is chosen to be simple to test and easy to grow.

## 2. Concurrency

The host has two pools, so network work and box work never steal from each other.

- **Network threads** run one Asio `io_context`: accepting, reading, writing, and keep-alive. They never run a box.
- **Box threads** are a separate pool. A request that reaches a box route is posted to it, runs there, and its response is posted back to the connection. Box threads can be pinned to cores (`threads.pin-boxes` in the host config), which is how the human gets Linux to keep black boxes hot.
- **v1 runs each box call to completion on a box thread.** wasmtime can suspend a call (its async support runs WASM on a fiber and yields at host calls and epoch deadlines), which is the path to the human's model: many boxes checked out at once, each blocked on an event without holding a thread. v1 doesn't do this yet, since no v1 host function waits on anything. The seam is the box pool's interface, which takes a job and a completion.

Supersedes nothing; it settles `010.Manifest.md` § Start with Hello World's "blocking database thread" for now.

## 3. The box boundary (goober-abi@1, v1 subset)

A box may import only from module `goober`, and only the functions below. The host refuses any other import at upload, including every WASI module. A box gets nothing it isn't given. (Q4)

| import | signature | does |
| --- | --- | --- |
| goober_request_size | () -> i32 | The size of the request document. |
| goober_request_read | (ptr i32, len i32) -> i32 | Copies the request document into box memory and returns the bytes copied. |
| goober_respond | (status i32, type_ptr i32, type_len i32, body_ptr i32, body_len i32) -> i32 | Sets the response. The last call wins. Returns 0, or -1 for a bad status or pointer. |
| goober_header_set | (name_ptr i32, name_len i32, value_ptr i32, value_len i32) -> i32 | Adds a response header. Host-owned headers (set-cookie, content-length, connection, transfer-encoding, and anything under goober-) are refused with -1. |
| goober_now_ms | () -> i64 | The request's time, fixed once when the request arrives, so every call in one request sees the same time. |
| goober_random_fill | (ptr i32, len i32) -> i32 | Fills memory with bytes from a generator seeded per request. The seed is written to the access log, so a request's randomness can be replayed. |
| goober_log | (level i32, ptr i32, len i32) -> i32 | Captures a log line. Lines are side effects: they are written to the box's log after the call, like an outbox element, and never interleave with other requests. |

Every pointer is checked against the box's memory. A bad pointer returns -1 and never traps the host.

**Modules** arrive as binary WASM, recognized by the `\0asm` magic, or as WAT text, which the host converts and stores as binary.

**Exports.** A box exports `memory`, and one function per route: `goober_route_$name`, taking nothing and returning i32, where 0 means it ran, and anything else becomes a 500. This is the reactor contract: each route has its own handler, as the human leaned in Q7, so there is no signal table. An optional `goober_on_start` runs once per instance before the route.

**The request document** is JSON for v1, so the boundary can be played with before the struct layouts of `120.TheBoundary.md` are generated:

```json
{
	"request_id": "9f3c...",
	"method": "get",
	"path": "/hello/world",
	"params": { "name": "world" },
	"query": { "q": "x" },
	"headers": { "accept": "text/html" },
	"body": "",
	"domain": "localhost",
	"tenant": "playground"
}
```

Typed int64 parameters arrive as strings, as `021.PrimaryKeys.md` § Ids in JSON are strings wants. The struct-and-pickup layout of 120 replaces this document when the generators exist; the import names stay.

**Determinism.** Time, randomness, and logs are all host-controlled, so the only thing a box sees that isn't a pure function of its request and its seed is how long the host takes to answer. (Q6)

**Generated names.** Generated code lives under `gen_$schema_$method` and `goober_` (Q5). No generator ships in v1; the boundary is small enough to write by hand in WAT or C.

## 4. Limits

Every WASM parameter has a host default, and a manifest may lower or raise it up to a host maximum (Q8):

| behavior field | host default | host maximum | enforced by |
| --- | --- | --- | --- |
| timeout-ms | 1000 | 10000 | Epoch deadline. |
| fuel | 100,000,000 | 2,000,000,000 | wasmtime fuel. |
| memory-max-bytes | 64 MiB | 512 MiB | The store's limiter. |

The WASM stack is engine-wide, at 512 KiB, so a manifest can't change it. A trap in `goober_on_start` fails the request with a 500 and is logged. Every call runs in a fresh store and instance, so nothing leaks from one request to the next. That is solo, which is the only lifecycle in v1.

## 5. Names

- **Every name is unique within a host, and bad names are refused.** Box names, route names, and tenant names can't repeat across the host. A new version of the same box may reuse its own names. (Q10)
- **Tenant names, box names, and route names** match `[a-z][a-z0-9_]*`, at most 63 characters, and may not start with `goober_`. (Q13) This is narrower than `150.DeepManifest.md` § Rules every field obeys, which allows any identifier for chosen names. The two need reconciling: v1 refuses capitals in route names.
- **Host-owned names** start with `_`, like the `_host` content tree below, so they can never collide with a tenant.

## 6. Configuration

One JSON file holds the whole host configuration. On SIGHUP, the host rereads it. The domains, operations token, and box limits take effect at once. A change to the listen address, storage path, threads, or `limits.body-max-bytes` is logged and needs a restart. A port of 0 picks any free port, which the tests use. (Q11, Q46)

```json
{
	"listen": { "address": "127.0.0.1", "port": 8080 },
	"storage": "./storage",
	"platform-domain": "localhost",
	"domains": {
		"localhost": { "tenant": "playground" },
		"127.0.0.1": { "tenant": "playground" }
	},
	"operations": { "token": "change-me" },
	"threads": { "network": 2, "boxes": 4, "pin-boxes": false },
	"limits": {
		"body-max-bytes": 1048576,
		"timeout-ms": { "default": 1000, "max": 10000 },
		"fuel": { "default": 100000000, "max": 2000000000 },
		"memory-max-bytes": { "default": 67108864, "max": 536870912 }
	}
}
```

The domain registry lives in this file for v1, which stands in for the `domains` table of `015.Domains.md`. The `Host` header, without its port, picks the domain, and the domain gives the tenant.

## 7. Storage and the host WAL

Everything the host owns is mirrored to disk, in a tree a person can read and an ordinary backup tool can copy. (Q12, Q18, Q29)

```
storage/
	wal/host.wal                                    the host WAL
	boxes/$box/active                               the active version id
	boxes/$box/versions/$version/manifest.json
	boxes/$box/versions/$version/box.wasm
	content/$tenant/$path                           static content
	content/_host/$path                             host-wide content, like error pages
	logs/access.log                                 one JSON line per request
	logs/boxes/$box.log                             captured goober_log lines
	sqlite3/$tenant/internal.db                     (next) host tables per tenant
	sqlite3/$tenant/databases/$database/$version.db (next) a database at a schema version
```

**The host WAL makes every file change crash-proof.** A change is a bundle of file writes and deletes. The host appends the bundle's records to `wal/host.wal`, then a commit record, and fsyncs. Only then does it apply the writes, each by writing a temporary file, fsyncing it, and renaming it into place. Last, it appends a done record. On start, the host replays every committed bundle that has no done record. Applying a bundle is idempotent, so replay is always safe. A bundle with no commit record is discarded, and so is a torn tail with a bad checksum. When every bundle is done and the file passes 64 MiB, the host truncates it.

This is the human's design from Q22 and Q23, applied first to files. The same WAL becomes the bundle log for databases and the outbox: write the whole bundle, commit, execute, and mark it done. Litestream runs beside each SQLite file as a sidecar, and the host will manage it later.

**Records** are framed as `u32 length, u32 crc32, payload`, all little-endian. The payload is `u8 kind, u64 bundle, u32 path length, path, u32 data length, data`. The kinds are write = 1, delete = 2, commit = 3, and done = 4. Paths are relative to the storage root, and any path containing `..`, a leading `/`, or an empty segment is refused.

## 8. HTTP

- **Normalizing a path** (Q50): collapse runs of `/` into one, then trim a trailing `/` except at the root, then percent-decode each segment. A segment that decodes to `/`, NUL, `.`, or `..` is refused with a 400. Matching is case-sensitive.
- **Matching:** the number of segments decides the candidates. Within them, a literal segment beats a parameter at the first position where they differ, so `/jobs/new` beats `/jobs/{slug : string}`. An int64 parameter matches only an optional `-` followed by digits that fit in 64 bits.
- **Conflicts** are refused at upload: two routes on overlapping domains with the same verb and the same shape (the same literals in the same places, and parameters in the same places) conflict, whatever the parameter types.
- **Order of answer:** a box route first, then static content, then 404. GET on static content also answers HEAD.
- **Reserved prefixes** from `041.ReservedRoutes.md` can't be declared by a box: `/.well-known/`, `/oauth/`, `/identity/`, `/mcp`, `/goober/`, `/goober-operations/`, `/goober-operations-mcp`, `/internal/`, and `/error-message/`, which is added here.
- **Error pages** (Q51): when the host answers 4xx or 5xx, it serves `error-message/$status.html` from the tenant's content, then from `_host`, and otherwise a generated page that says "Uh Oh!". A box's own 4xx or 5xx response is passed through as the box wrote it.
- **Static content** has its content type inferred from the extension, an ETag of the first 16 hex digits of its SHA-256, `If-None-Match` support, and `Cache-Control: no-cache`. A request for `/a` serves the file `a`, or else `a/index.html`. The root serves `index.html`.

## 9. MCP and the operator API

`/goober-operations-mcp` speaks MCP over streamable HTTP: JSON-RPC 2.0 in a POST, answered with `application/json`. Every call carries `Authorization: Bearer $token`, with the token from `operations.token` or one minted by `goober-host token create` (006 §5). Every token acts as host:owner. This replaces the host identities of `410.API.md` for operators. The identity tools (`realm_get`, `role_grant`, `role_revoke`, `sessions_revoke`) are in 006 §5.

| tool | does | in 410 |
| --- | --- | --- |
| host_health | Uptime, counts, storage path. | Yes |
| domain_list | The domains from the config, with their tenants. | Yes |
| content_put | Writes one static file for a tenant, from text or base64, through the host WAL. | New |
| content_get | Reads one static file. | New |
| content_list | Lists a tenant's static files, optionally under a prefix. | New |
| content_delete | Deletes one static file through the host WAL. | New |
| version_upload | Uploads a manifest and its module (base64 WASM, or WAT text for play), checks them, stores them, and makes the version active. | Yes, with promotion folded in |
| version_list | Lists a box's versions, and which is active. | Yes |
| version_get | Returns a version's manifest. | Yes |
| version_promote | Makes an existing version active, which is how v1 rolls back. | Yes |
| box_list | Lists boxes and their active versions. | New |
| box_logs | Returns the newest lines of a box's log. | New |
| access_log | Returns the newest lines of the access log. | New |

**Approval in v1 is a dev policy:** the operator token is trusted, so an upload that passes the checker goes live at once. The human wants an operator UI (Q57), which comes later and adds the approval step of `305.Approvals.md`. The content tools write straight to disk rather than through the working set of `320.WorkingSet.md`, which is the simplest thing that lets an agent build a site. Both shortcuts must be retired before anyone else uses the host.

## 10. The v1 manifest

v1 reads this subset of `150.DeepManifest.md`:

```json
{
	"box": "hello",
	"mission": "Say hello.",
	"domains": ["*"],
	"behavior": { "timeout-ms": 500, "fuel": 10000000, "memory-max-bytes": 16777216 },
	"routes": {
		"http": {
			"/hello/{name : string}": {
				"get": { "name": "say_hello" }
			}
		}
	}
}
```

Verbs are get, post, put, patch, and delete. Parameter types are string, int32, and int64. Top-level fields from 150 that v1 doesn't implement (data, external, keys, static, and so on) are accepted with a warning, so manifests from the docs still load. Any field 150 doesn't define is refused.

## 11. Decided, not built in v1

These answers are recorded here so the data work starts from them.

- **The schema format** (Q14) is JSON. One file per schema version holds tables, columns with 036 types, defaults, nullability, indexes, and the host-minted id. A table may be marked as a source.
- **Route-to-strategy binding** (Q15): route parameters feed strategies as variables. A route that reaches a strategy needing a parameter it doesn't have fails at runtime. The checker raises a yellow warning, and an `incomplete_data_access` counter counts each failure.
- **Caller-chosen ids** (Q16): the per-tenant database is the guardrail. {name} is allowed inside a tenant's database, and the checker flags it for audit.
- **Roles** (Q17): a requirement is a disjunction of conjunctions. `owner/{!tenant}` is reachable by anyone who holds that grant. The human sees no contradiction.
- **Write sets** (Q22, Q23): writes are buffered, written to the host WAL as one bundle, executed, and marked done before the response leaves.
- **Databases** (Q24, Q25): created on demand. Two boxes may share one, since each file has its own lock. Schemas are their own artifact with their own log, bound by version, and only expand in v1 (Q43).
- **Ids** (Q26): one database vends id ranges. Composite keys are a door left open.
- **by_index reads** (Q27) are iterators, so the host controls paging and buffering.
- **Sources** (Q31 to Q38): an event shape only gains columns. Sources hold no personal data and are kept forever. Each source is one event type. Operators can delete an event. Failing events can be marked poison and skipped, under a per-source policy. A shadow gets its own cursor and commits nothing. Cursors live in a `goober_` table in the tenant database. These change `023.Sourcing.md` § The cursor, which says a failure stalls the handler rather than skipping the event.
- **Old readers** (Q39): reads may be lossy, using defaults for dropped columns, so an old one-shot WASM keeps running as long as possible.
- **Sessions** (Q44): a cookie holding an opaque token, set as `__Host-` with Secure, HttpOnly, and SameSite=Lax, with every user-facing setting in the host config and overridable per tenant.
- **Mail** (Q45): the dev mailer writes a log line pointing at a MIME file. Amazon SES is the first real provider. Providers are pluggable.
- **Sign-in styling** (Q47): one host-owned template, styled by a per-domain config file fetched as static content.
- **Operator dive** (Q49): a handshake in which a tenant domain is made to vend a short-lived token for the operator.
- **The vault** (Q59): a SQLite database. Each key is an encrypted JSON bundle prefixed with 64 random bytes, under a key from the host config for now.
- **Timers** (Q55): a row per timer in the tenant's database, and a cached tzdata the operator can update or replace with the OS copy.
- **Contradictions** (§H): pick whatever is simplest to test, case by case, as the code reaches each one.

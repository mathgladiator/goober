# Telephony

A design proposal, not built. The human asked for it on 2026-10-28: each tenant will have a
phone number at some point, which means new routes and new host permissions. It follows
the shape of mail. Texts and calls arrive as routes on a box, as mail does in
`024.MailIn.md`. Boxes send texts through a service in the outbox, as they send mail in
`018.Mail.md`. The host rents the edge (`099.TheSystem.md`): a carrier API provider owns
the numbers, the radio, and the phone network, and the host owns everything a box can see.

Nothing here is decided until the human ratifies it. The decisions that are costly to
reverse are collected in § 11 and in `design/QUESTIONS.md` (Q42 to Q49).

## 1. What a tenant gets

- **A number.** It is a real E.164 number (`+18165551234`) that the host rents from the
  provider and assigns to one tenant. A tenant may hold several, for example a local number
  and a toll-free one. A number belongs to exactly one tenant at a time.
- **Texts in.** An SMS or MMS to the number runs a box route. The box sees the sender's
  number, the text, and any pictures, which are stored as attachments.
- **Calls in.** A call to the number runs a box route. The route answers with a short script
  in a fixed vocabulary: say, play, gather digits, record, forward, or hang up. A box never
  speaks the provider's markup.
- **Texts out.** A box sends a text through a `phone` service, after commit, within limits.
- **Not at first:** outbound calls, conferencing, real-time audio to a box, and numbers
  outside the US and Canada (§ 10).

## 2. The path of a text and a call

```
caller ── carrier ── provider ──HTTPS webhook──▶ /goober/phone/$provider/{sms,voice,status}
                                                    │  signature checked; number → tenant
                                                    ▼
                                          host: STOP/HELP, opt-outs, limits
                                                    │
                                                    ▼
                                         box route (routes.phone), as for mail
                                                    │  its answer
                                                    ▼
                         reply text (outbox) · call script (rendered as provider markup)
```

**The webhooks are public.** Mail's hook lives under `/internal/`, which only the host's own
infrastructure reaches. The provider calls from the internet, so its hooks live under the
host-owned `/goober/phone/$provider/` prefix. Every request must carry the provider's
signature: Twilio signs with HMAC-SHA1 over the URL and form (`X-Twilio-Signature`), and
Telnyx signs with Ed25519 over the timestamp and body (`telnyx-signature-ed25519`). A request
without a valid signature, or with a timestamp more than 5 minutes off, is a 403, and the box
never wakes. *This extends 041, whose `/goober/` holds host features for browsers and
agents; the alternative, a new top-level prefix such as `/goober-phone/`, needs 041 changed
instead.*

**Number to tenant.** The `To` number is looked up in the host's number registry (§ 5). A
number the host doesn't hold is refused before any box runs: a 200 with an empty reply, so
the provider doesn't retry.

## 3. Phone routes

```json
"routes": {"phone": {
  "sms": {
    "*":            {"receive": {"name": "text_in", "public": true, "media": 3}},
    "+18165551234": {"receive": {"name": "orders_text", "public": true}}
  },
  "voice": {
    "*":            {"answer": {"name": "call_in", "public": true, "timeout-ms": 4000}},
    "menu":         {"step":   {"name": "call_menu", "public": true}}
  }
}}
```

| field | meaning |
| --- | --- |
| `sms` key | `*` for every number of the tenants this box serves, or one E.164 number the tenant holds |
| `voice` key | `*` or a number for `answer`, the call's first route; any other key names a `step`, which only a script's `gather` or `record` can reach |
| `name` | the route's export, `goober_route_$name` |
| `public` | required, `true`: a caller isn't signed in |
| `media` | how many MMS pictures the route takes, 0 to 10; default 0, and more are refused |
| `timeout-ms` | the box's time, 1 to 5000; the provider waits about 15 s for the whole webhook |

**Which route.** A number's own route beats `*`. Two boxes may not claim the same number,
or `*`, for a tenant they share; the registry refuses the second at upload, as it does for
mail addresses. A box's numbers come from its tenants. A box with `"domains": ["*"]` serves
every tenant, so its `*` would take every tenant's texts, and upload refuses phone routes on
such a box (Q45).

**What an SMS route gets.**

```json
{"from": "+19135550000", "to": "+18165551234", "text": "Is Rye open Sunday?",
 "media": [{"id": "att_…", "type": "image/jpeg", "bytes": 81233}],
 "message_id": "SM…", "received_at": "2026-10-28T21:48:50Z", "segments": 1}
```

`from` is the carrier's claim, not a verified principal: numbers can be spoofed, more easily
on calls than on texts. A box that wants to know the person proves the number the way
sign-in proves an address, with a code (Q48), and `{!user_id}` stays empty until then.

**The SMS route's answer.**

| the box | what happens |
| --- | --- |
| 2xx with `{"reply": "text"}` | the reply is sent to `from` after commit, counted against the limits (§ 6) |
| 2xx, no reply | nothing is sent |
| 4xx | nothing is sent, and the box's error is logged |
| 5xx, a trap, a timeout | nothing is sent, the provider is answered 200, and the failure is in `box_logs`; texts aren't retried, since a sender would get a duplicate reply |

## 4. Calls: the script vocabulary

A voice route answers JSON, `{"script": [...]}`. The host checks it and renders it as the
provider's markup (TwiML or TeXML). The vocabulary is closed:

| step | fields | notes |
| --- | --- | --- |
| `say` | `text` (1 to 1000 characters), `voice`? (`female` or `male`), `language`? (`en-US` or `es-US`) | text to speech |
| `play` | `attachment` (an audio attachment id of the tenant's) | mp3 or wav, at most 5 MiB |
| `gather` | `digits` (1 to 20), `timeout-s`? (1 to 15), `next` (a `step` route name), `prompt`? (a `say`) | the digits go to `next` as `{"digits"}` |
| `record` | `max-s` (1 to 300), `next`, `beep`? | the recording becomes an attachment, and `next` gets `{"recording": {"id", "seconds"}}` |
| `forward` | `to` (E.164), `timeout-s`? | only to numbers on the tenant's forward list (§ 5) |
| `hangup` | | also the implicit end of every script |

**The call is the context.** Each step route gets
`{"call_id", "from", "to", "step", "digits"?, "recording"?, "started_at"}`. `call_id` is the
host's own id (`{!call_id}`, reserved; the provider's id stays in the host), so a box keeps
state across steps in its own tables, keyed by it. A call runs at most 20 steps and 30
minutes, and the host hangs up after either.

**Failure is spoken, not silent.** If a box fails, times out, or answers a script that
doesn't check, the caller hears the host's own line, "Sorry, this number can't take calls
right now", and the call ends. The failure is in `box_logs` with the call id.

**Recording law.** Several US states require every party's consent to record. A script with
`record` must `say` or `play` something before it, and upload warns if a route's scripts
can't be checked for that. The host doesn't judge whether the notice is adequate (Q47).

## 5. Host permissions

Two kinds of new permission: the operator's, over numbers and money, and the tenant's, over
what its boxes may do with a phone.

**Operator actions are host roles (013).** Renting a number costs money every month, and
forwarding a call can cost money per minute, so these need a host role:

| operator tool | role | what it does |
| --- | --- | --- |
| `phone_numbers_search` | `host:operator` | available numbers by area code or region, with the monthly price |
| `phone_number_rent` | `host:owner` | rents one number; the price is read back, and the call carries `confirm_monthly_usd` equal to it |
| `phone_number_assign` | `host:owner` | gives a rented number to a tenant, or takes it back |
| `phone_number_release` | `host:owner` | gives the number back to the provider; it can't be undone, and the number may be gone for good |
| `phone_grant_set` | `host:owner` | sets a tenant's phone grant, below |
| `phone_status` | `host:operator` | numbers, tenants, 10DLC state, this month's spend, opt-out counts |
| `phone_log` | `host:operator` | the newest texts and calls, with numbers |

The grant and rental tools are `host:owner` only, so an agent signed in as an operator
(Grok, `023.OperatorOAuth.md`) can look but can't spend. Whether to name a new role, such as
`host:billing`, is Q44.

**A tenant's grant is host config.** It says what boxes serving that tenant may do, and every
limit is the host's to set, never the manifest's:

```json
"phone": {
  "provider": "telnyx",
  "tenants": {
    "shop": {
      "sms-in": true,
      "sms-out": {"daily-max": 200, "per-number-daily": 5, "countries": ["US", "CA"]},
      "mms": true,
      "voice-in": true,
      "record": false,
      "forward-to": ["+18165550100"],
      "monthly-usd-cap": 25
    }
  }
}
```

**Upload checks the grant.** A version whose manifest declares `routes.phone.sms` for a
tenant without `sms-in`, a `voice` route without `voice-in`, or a `phone` service without
`sms-out` is refused at upload, naming the missing grant. That is the same move as keys
bound to hosts (Q35): the manifest says what it wants, and the host config says what it may
have. A script's `forward` to a number off `forward-to` fails at run time with the spoken
failure, since scripts are data the box makes per call.

**The spend cap is the host's own ledger.** The host counts segments, minutes, and numbers
at the provider's list prices in `storage/phone/ledger.db`. Past `monthly-usd-cap`, texts out
wait as a 429, and calls in hear the failure line. The provider's own account limits are a
second wall; the host's count isn't billing truth, and `phone_status` shows both.

## 6. Texts out

```json
"external": {"phone": {"phone": {}, "methods": {"send": {"budget": {"calls": 1}}}}}
```

```
goober_call("phone", "send", {"to", "text", "media"?: [attachment ids]}) -> {"accepted": true, "key"} or {"error"}
```

- **Checked in the call:** `to` is E.164 in an allowed country. The text is 1 to 1600
  characters, at most 10 segments; GSM-7 text runs 160 characters a segment and anything
  else 70. Media must be the tenant's image attachments, at most 3, 600 KiB in all.
- **Sent after commit:** an outbox element (verb `SMS`), retried on the provider's 5xx and 429
  for an hour. A refusal (a landline, an opted-out number, a blocked carrier) is a dead
  letter. The idempotency key is the provider's idempotency header where it has one, so a
  retry can't send twice.
- **From the tenant's number.** The box never chooses the sender. A tenant with several
  numbers sends from the one the conversation came in on when the box passes `reply_to`
  (a message id), and otherwise from its first number.
- **Within limits:** `daily-max` per tenant, `per-number-daily` to one recipient (counted by a
  hash of the number, as mail does), and the spend cap.
- **Opt-outs first:** a number that texted STOP to the tenant's number is refused before
  anything is queued (§ 7).
- **Quiet hours** (Q46): a marketing text to a US number outside 8am to 9pm in the
  recipient's area code's time zone waits until morning. Whether the host or the box judges
  "marketing" is open.

## 7. STOP, HELP, and the carriers

Carriers require some things of every number that sends texts, and the host does them before
any box sees the message, so no box can forget:

- **Opt-out keywords:** STOP, STOPALL, UNSUBSCRIBE, CANCEL, END, and QUIT, alone in the
  message and in any case, record an opt-out for that sender and tenant number. The
  confirmation reply is a host template, `phone-stopped` (`022.MailTemplates.md`'s machinery
  with a text part only). The box gets `{"opted_out": true}` on an event route if it
  declares one.
- **Opt back in:** START, UNSTOP, and YES clear the opt-out.
- **HELP and INFO** answer with the tenant's `phone-help` template: who they are and how to stop.
- **The opt-out ledger:** `storage/phone/optouts.db`, keyed by a hash of the sender's number
  and the tenant's number, kept forever. It is the one place the host must remember a number.
- **10DLC.** In the US, application-to-person texts from a local number need a registered
  brand and campaign, or carriers filter and fine. Registration needs a business's legal
  name, its EIN, and samples of the messages, and takes days to weeks. The host records each
  number's campaign state and refuses `sms-out` until it is approved. A toll-free number
  with toll-free verification is the alternative path. Registration itself is the operator's
  job in the provider's console; the host only reads the state (Q43).

## 8. What is stored and logged

| what | where | how long |
| --- | --- | --- |
| numbers, assignments, grants | host config, `storage/phone/numbers.db` | while held |
| opt-outs | `storage/phone/optouts.db` (hashed numbers) | forever |
| spend ledger | `storage/phone/ledger.db` | 13 months |
| MMS pictures, recordings | attachments of the tenant | `phone.media-days`, default 30, unless a box keeps them |
| message and call metadata with numbers | `logs/phone.log`, like `logs/mail.log` | log rotation |
| the egress log | `phone:` with no numbers | as now |

Message bodies are not kept by the host. A box keeps what it stores. Recordings are personal
data in most places and are deleted on schedule like mail attachments. Backups carry all of
it (`019.Backups.md`).

**Keys.** The provider's API key and webhook secret or public key live in the key store as
`keys/system/phone/$provider/...`, bound to the provider's API host (`064.Keys.md`, Q35), and
are set on the machine only, like the AWS keys of 018.

## 9. Testing without a carrier

- **A fake provider.** `fake_phone_provider.py` signs webhooks with a test key, posts texts
  and call steps, and captures the host's outbound API calls, as `fake_mta_hook.py` does for
  mail.
- **`just phone-e2e`:** a text in gets a reply; STOP blocks a send; a call walks through
  `gather` to a `step` and `record`; forwarding off the list is refused; an upload without
  the grant is refused; the spend cap stops a send.
- **Unit tests** for each package: signature checks with the providers' published vectors,
  script checking and rendering, segment counting, the keyword parser, and the opt-out ledger.
- **The provider's sandbox,** for a manual check against the real API before a number
  is rented.

## 10. Not in the first build

- **Outbound calls.** A box placing calls is the most abusable feature here (robocalls, toll
  fraud), and E911 rules attach to numbers that place calls. It waits for a reason.
- **Real-time audio** to a box (media streams, voice agents). That is a streaming protocol the
  boundary (`120.TheBoundary.md`) doesn't have.
- **Numbers outside the US and Canada,** whose regulations differ per country.
- **Sign-in by phone.** Proving a number with a code is easy to add once 013's identity takes
  numbers beside addresses (Q48), but SMS codes are weaker than email codes (SIM swaps).
- **Group MMS, RCS, and WhatsApp.**
- **Porting a number in** from another carrier: it works at the provider, but the host gains
  nothing until the number is rented in its account.

## 11. Decisions for the human

These are the costly-to-reverse choices, each recommended, none taken.

1. **Provider (Q42).** Twilio has the broadest documentation, the most examples an agent knows,
   and higher prices. Telnyx owns its network, is cheaper per text and minute, signs webhooks
   with Ed25519, and has TeXML, which is TwiML-compatible. SignalWire and Plivo are smaller.
   *Recommended: Telnyx,* with the script vocabulary rendered by a per-provider adapter so a
   switch is a host change, not a box change.
2. **10DLC or toll-free first (Q43).** 10DLC needs a brand per business; one host-owned brand
   for every tenant is against carrier rules when tenants are different businesses.
   *Recommended:* one toll-free number per tenant to start, verified per tenant, since it skips
   brand registration and suits low volume; local 10DLC numbers once a tenant needs a local
   presence.
3. **Who may spend (Q44).** *Recommended:* rental, release, and grants are `host:owner` only,
   with no new role until a second person operates the host.
4. **Boxes with `"domains": ["*"]` (Q45).** *Recommended:* such boxes may not declare phone
   routes, so a number's traffic goes to a box that names its tenant's domains.
5. **Quiet hours and "marketing" (Q46).** *Recommended:* the host enforces 8am to 9pm for
   every text a box starts, and replies to a text that just came in are exempt, since the
   person wrote first.
6. **Recording notice (Q47).** *Recommended:* `record` requires a `say` or `play` before it,
   and `record` is off in the grant by default.
7. **Phone numbers as identity (Q48).** Not now. When it comes, it is a second kind of proved
   contact on the same account, and never a password reset.
8. **The webhook prefix (Q49).** `/goober/phone/$provider/` under 041's `/goober/`, or a
   prefix of its own. *Recommended:* `/goober/phone/`.

## 12. Build order, once ratified

1. The number registry, grants in the host config, operator tools, and upload checks, all
   without a provider. Nothing sends.
2. The provider adapter: signatures, the API client, and the fake provider.
3. Texts in: routes, keywords, opt-outs, MMS as attachments, and replies.
4. Texts out: the `phone` service, outbox verb `SMS`, limits, the ledger and cap.
5. Calls in: the script vocabulary, steps, recording, forwarding, and failure lines.
6. Deploy: the provider's key on the machine, the webhook URL set at the provider, and
   `just phone-e2e` against the fake. Then one real number for one tenant.

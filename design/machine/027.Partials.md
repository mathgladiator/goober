# Shared partials

A design, built the same day. GrokBot asked for it on 2026-10-28: adding one nav link to
a site took 23 writes (22 whole documents re-put, plus `site.json`), and the box pages
(`/search`, `/places`) keep their own copy of the nav, which drifts and needs a deploy to
change. The human asked for this design and then for it to be built.

## 1. What a partial is

A partial is a piece of HTML a tenant writes once and every page includes: a nav, a footer,
a banner. It is a file in the tenant's content tree at `_partials/$name.html`. Like every path
segment starting with `_`, it is never served by itself. `$name` is 1 to 64 of
`[a-z0-9_-]`.

The operator tools write and read partials. The previous ten versions of each are kept for
rollback:

| tool | does |
| --- | --- |
| `partial_put` `{tenant, name, html}` | writes it, keeping the old one as a version; answers the new etag and the previous etag |
| `partial_get` `{tenant, name, version?}` | the current text and etag, or a kept version's |
| `partial_list` `{tenant}` | every partial: name, etag, bytes, kept versions, and the pages whose bodies include it |
| `partial_delete` `{tenant, name}` | removes it; its versions stay, so a delete can be undone |

`content_put` to `_partials/nav.html` works too, but keeps no version.

## 2. Including one

A page includes a partial with one marker, in the style of server-side includes:

```html
<!--#include nav-->
```

Spaces around the name are allowed (`<!--#include nav -->`).

The host expands markers in HTML it serves:

| HTML | expanded |
| --- | --- |
| a page: a document, a fragment or markdown page through its template and layout, a listing | always |
| a box route's JSON rendered through a template (007 § 8) | always: the host rendered it, and every value in it was escaped, so a marker can only come from the template |
| a box route's own `text/html` response | only when the route says `"includes": true` |
| JSON, XML, text, static files, attachments | never |

**One level.** The partial's own markers are not expanded, so no partial can include itself
or start a loop.

**Raw.** The partial is spliced as written. It is the tenant's own HTML, written by an
operator; no person's input reaches it.

**Missing.** A missing partial expands to nothing, never a 500. The response carries
`x-goober-partial-missing: nav`, and the access log line names it.

## 3. The active link

Links in a partial can say which pages they belong to:

```html
<nav>
  <a href="/" data-match-exact="/">Home</a>
  <a href="/places" data-match="/places">Places</a>
  <a href="/future-of-meat" data-match="/future-of-meat" data-key="future">The future of meat</a>
</nav>
```

When the partial is expanded for a request, the host picks the link that best fits the
request's path:

- `data-match-exact="/x"` fits only `/x`.
- `data-match="/x"` fits `/x` and everything under it (`/x/y`), not `/xy`.
- Paths are compared without the query and without a trailing slash; `/` stays `/`.
- The longest fitting value wins. An exact fit beats a prefix of the same length.
- Ties all win.

The winning links get `aria-current="page"`, and `active` is added to their `class`. That
means appending to an existing `class` attribute, or adding `class="active"`. Nothing else
in the partial changes.

**A page can name its link instead.** A page with `<meta name="nav-key" content="future">`
marks the links whose `data-key` is `future`, whatever the path. A box's HTML can carry the
same meta tag.

## 4. Signed in: `@auth`

When `_partials/nav@auth.html` exists, a signed-in visitor gets it in place of
`_partials/nav.html`. The page's answer then depends on the cookie, so the host sends
`cache-control: private, no-cache` and `vary: cookie` on it. That happens even on a public
page, and even for a signed-out visitor, since a shared cache must never hand one person's
version to another.

## 5. ETags

A page's ETag is a hash of the bytes it serves, computed after expansion, and so is a box
route's. So:

- one `partial_put` changes the ETag of every page that includes it, with no page re-put;
- two paths that mark different active links have different ETags;
- a 304 still means the visitor has exactly these bytes.

## 6. Checking it

- `page_render` shows a page expanded, as served for its URL, so a partial can be checked
  before anyone sees it.
- `route_check` lists, for a page, the partials its body includes (`partials`). For a box
  route, it says whether `includes` is on.
- `partial_list` shows which pages include each partial.

## 7. What is left out

- **Nesting and parameters.** A partial can't take arguments or include another. A tenant
  needing two navs writes two partials.
- **Several partials in one write.** Each `partial_put` stands alone. Because ETags follow the
  bytes, a visitor between two puts sees a consistent page; the second put lands a moment
  later.
- **Mustache's `{{> name}}`** keeps reading `_templates/`. A template that wants the shared nav
  uses the marker, which also gets the active link.

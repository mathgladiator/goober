# 024. Mail in: Stalwart, the MTA hook, and mail routes

Status: built, at the human's request on 2026-10-28 ("let's get all that working so I can have
the box get email and define routes"). It implements 038.Mail.md's inbound half. Where this
differs from 038, the difference is called out.

## 1. The path of a message

```
sender's MTA --SMTP:25--> Stalwart --MTA hook (HTTP, loopback)--> goober-host --> the route's box
```

Stalwart owns SMTP: TLS, the queue, and parsing the conversation. It calls the host's hook at
two stages, RCPT and DATA, at `http://127.0.0.1:$port/internal/routes/mta/stalwart`, with a
bearer token. The host answers each with what Stalwart should say.

The hook is reachable only:

- when `mail.inbound.token-file` is set in the host config (otherwise 404),
- from a loopback address, with no `X-Forwarded-For`, `Forwarded`, or `Via` header (anything
  that came through Caddy carries one), and
- with `Authorization: Bearer` and the token in that file (at least 32 characters, compared in
  constant time).

Every refusal is a bare 404, so the path reveals nothing from outside.

## 2. Mail routes

```json
"routes": {"mail": {
  "support@kcmeatup.com": {"receive": {"name": "support_inbox", "public": true, "max-bytes": 10485760, "attachments": 5}},
  "support@": {"receive": {"name": "support_any", "public": true}},
  "reply+{ticket : token}@": {"receive": {"name": "ticket_reply", "public": true}},
  "orders+{id}@": {"receive": {"name": "order_mail", "public": true}},
  "*@": {"receive": {"name": "inbox", "public": true, "automatic": true, "timeout-ms": 3000}}
}}
```

| field | meaning |
| --- | --- |
| the key | the address pattern: `local@domain`, `local@` (every domain the box serves), `*@` or `*@domain` (catch-all), with `{name}` parameters (`[a-z0-9._-]`, 1 to 64) and at most one `{name : token}` |
| `name` | the route's export, `goober_route_$name` |
| `public` | required, `true`: senders aren't signed in (038) |
| `max-bytes` | the largest message, 1024 to 25 MiB; default 10 MiB |
| `attachments` | how many attachments the route takes, 0 to 100; default 0 |
| `automatic` | whether auto-replies, bounces, and reports reach it; default false |
| `timeout-ms` | the box's time, 1 to 10000 |

Addresses are lowercase. A pattern's domain must be one of the box's domains. Mail-enabled
domains are the host config's `domains` (v1 has no per-domain switch).

**Which route.** For a recipient, the host considers every route of every box serving its
domain. A specific route beats a catch-all; then one naming the domain beats one that
doesn't; then more literal characters win. Two boxes may not claim the same address shape on
a domain they share: `support@` and `support@kcmeatup.com` collide, as do two `*@`. The
registry refuses the second at upload.

## 3. RCPT and DATA

**RCPT.** The host matches the recipient. If no route claims it, or its domain isn't the
host's, or its reply token is forged or expired, the answer is `550 5.1.1 No such recipient
here`, before the body is sent. A second recipient in the same transaction gets `452 4.5.3`:
one route decides each message, so its answer can be the SMTP answer, and the sending server
sends the others in transactions of their own (RFC 5321 § 4.5.3.1.10). *This differs from 038,
which doesn't say what happens to a message for several routes.*

**DATA.** In order:

1. A message past the route's `max-bytes` (or `mail.inbound.max-bytes`) is refused: `552 5.3.4`.
2. The MIME is parsed (`mail_inbound`): addresses, subject, ids, the first text/plain and
   text/html bodies (text is made from the HTML when there is none), and attachments.
3. Automatic mail (an `Auto-Submitted` other than `no`, `X-Autoreply`, `X-Autorespond`,
   `Precedence` of `auto_reply`, `bulk`, or `junk`, a `multipart/report`, or an empty
   envelope sender) is answered "discard" for routes without `"automatic": true`: the sender
   hears 250, and nobody hears anything else, so loops end there.
4. More attachments than the route takes: `550 5.3.4`.
5. Attachments are stored in `storage/mail/inbound.db`, with the box, route, tenant, name,
   type, size, and SHA-256. They are kept `mail.inbound.attachment-days` (default 30).
6. The box runs.

**The box's answer.**

| the box | Stalwart is told | the sender hears |
| --- | --- | --- |
| 2xx, or no response | `discard` | 250: Stalwart keeps nothing, the box has it |
| 4xx (but 429) | `reject` | `550 5.7.1` and the box's `{"error"}`, printable ASCII, 200 bytes |
| 429, 503, a 5xx, a trap, a timeout | `reject` | `451 4.3.0`: try again later |

The box's writes commit as for any request: kept below 500, rolled back at 500 and above, so
a deferred message leaves nothing behind and is delivered whole when it comes again. A
refused or deferred message's attachments are deleted.

## 4. What the box gets

The request document has `method` "receive", `path` "mail:$recipient", `params` from the
address (and a token's claims), `domain`, `tenant`, `user` null, and `mail`: `{to, sender}`.
`to` is the reserved `{!to}`; `sender` is `{!sender}` (§ 5). The body is the message as JSON:
`to`, `envelope_from`, `from` `{address, name}`, `sender`, `to_list`, `cc`, `reply_to`,
`subject`, `text`, `html`, `message_id`, `in_reply_to`, `references`, `date`, `attachments`
(`id`, `filename`, `content_type`, `bytes`, `inline`, `content_id`), `automatic`, `truncated`,
and `bytes`. A token route's body also says `reply_from_recipient`.

The bytes of an attachment come from the mail service's `attachment` method, which every
mail service has: `{"id"}` answers `{filename, content_type, bytes, base64}`, at most 8 MiB,
only to the box that received it, in its tenant. *038 lists a generated C struct and three
functions; in v1's JSON ABI they are the body and the status, as above.*

## 5. Senders

038 makes a sender that passes DMARC alignment a principal, `{!sender}`. Stalwart checks SPF
(HELO and MAIL FROM), DKIM, DMARC, and the client's reverse DNS on every message, but v1.0.1
gives the hook none of the results: its `serverHeaders` is always empty, no expression the
hook's `enable` sees holds them, and its HTTP headers are fixed. So in v1 `sender` is always
null, and `from` is only what the message says. What would change that is Q39.

Stalwart still refuses outright failures where its checks are set to: they run `relaxed` (logged,
not enforced) in v1.

## 6. Reply tokens

`send` with `"reply": {"route": "ticket_reply", "params": {"ticket": "42"}}`:

1. The route must be one of the sending box's mail routes, with a `{name : token}` part, and
   `params` must hold that name (the claim) and every other parameter in the address.
2. The host draws an 8-byte id, MACs it (HMAC-SHA-256 under `storage/mail/reply.key`, 32
   random bytes made on first use, mode 0600, truncated to 7 bytes), and writes
   `reply+base32(id ‖ mac)@domain`, 24 characters for the token. The claims, the tenant, the
   box, the route, and the address it was sent to go in `storage/mail/inbound.db`, for 180
   days.
3. The address becomes the mail's Reply-To, and the call answers it as `reply_to`.

A reply's token is checked at RCPT: its MAC, then its row, which must name the same tenant,
box, and route and not have expired. The claims become the route's `params` (the claim, not
the token). *038 puts the claims in the token itself; a local part holds 64 characters, so
here the token is a handle and the claims stay in the host.*

## 7. Stalwart

`tools/stalwart.sh` installs, configures, and runs Stalwart **1.0.1**, pinned by version and
SHA-256 (`aabae69b...7d75`, GitHub's digest for `stalwart-x86_64-unknown-linux-gnu.tar.gz`).
Stalwart 1.0 keeps its settings as objects in its own store; `configure` starts a temporary
Stalwart in recovery mode, sets every object over its JMAP API, and stops it. It is safe to
rerun and reconciles objects by name.

| what | set to | why |
| --- | --- | --- |
| listeners | SMTP (STARTTLS) where asked; the admin API on loopback; nothing else | no IMAP, POP, submission, or web admin |
| MTA hook | the host's URL, stages rcpt and data, bearer token from a file, `tempFailOnError` | the host decides; if it can't answer, senders hear 451 and retry |
| relaying | only the host's domains (`--relay-domains`) | every goober domain is foreign to Stalwart |
| data | `maxMessageSize` 25 MiB, spam filter off | the box decides; the filter's verdict never reaches the hook |
| AUTH | off on every port | nobody signs in to send |
| sender checks | SPF, DKIM, DMARC, iprev `relaxed` on every port | logged; see § 5 |
| reports, routes | every report off, every outbound route local | Stalwart sends nothing |
| queue quota | 1 message of 1 byte | anything Stalwart would queue is refused with 452 4.3.1 |
| downloads | no spam rules, no ASN/geo database | nothing fetched at start |
| logs | stdout (the journal) | |
| TLS | file-backed, when given | STARTTLS with Caddy's certificate |

**Never an open relay.** Five layers, each holding if the one before fails: the hook refuses
every address the host doesn't serve at RCPT (and 451 if the host is down); the relay rule
names only the host's domains; at DATA the host answers only discard (with "250 2.0.0
Delivered") or reject, never accept; the one-byte queue quota refuses anything that would be
queued (tested by a hook that answers accept); and nothing routes outward.

**What Stalwart hands the hook** (confirmed by running it): headers as `[name, value]` pairs in
order, values raw (leading space, folding, CRLF); `contents`, the body alone, CRLF;
`size`, the whole message. Non-UTF-8 bytes are converted with `from_utf8_lossy`, so an 8-bit
body that isn't UTF-8 arrives with U+FFFD in it (base64 and quoted-printable bodies, which
nearly all mail uses, arrive intact). Stalwart's default throttles take 5 connections a
second from one address and 25 messages an hour from one sender domain to one recipient.

**On a server**, every `just deploy` (unless `--without-mail`), as root:

1. installs `iproute2` and `openssl`, and makes the `stalwart` system user (home `/srv/stalwart`);
2. installs or upgrades Stalwart (`stalwart.sh install`, a no-op at the pinned version), with
   its binary owned by root;
3. makes the hook token once (`$DIR/mail-hook.token` for the host, `/srv/stalwart/hook.token`
   for Stalwart, both 0600);
4. copies Caddy's certificate for the platform domain to `/srv/stalwart/tls`, or makes a
   30-day self-signed one until Caddy has one; `goober-stalwart-tls.timer` copies renewals
   daily and reloads them;
5. stops Stalwart and runs `configure` as `stalwart` inside a network namespace root makes, so
   recovery mode's listener (Stalwart binds it on every interface) never meets a network;
6. installs `stalwart.service` (port 25 by `CAP_NET_BIND_SERVICE`, `ProtectSystem=strict`) and
   starts it, sets `mail.inbound.token-file` in `host.json`, and restarts the host;
7. prints the MX records to add, one per domain, pointing at the platform domain, and a
   reminder that many providers block inbound port 25 until asked.

**Tests.** `just stalwart-e2e` runs the real Stalwart against a stand-in hook
(`tools/fake_mta_hook.py`) and checks every hook answer's SMTP reply, the payload's shape, the
queue quota, and a hook that is down. `just mail-e2e` runs the real Stalwart against a real
goober host with a box of mail routes, over SMTP. `mail_in_test` covers the hook in the
host's suite.
